# CPU／CUDA 批次最佳化與品質驗證

使用者範圍：保留既有標準功能，優先 CPU／CUDA，MLX 不更動。不推送、不發布、不刪除模型。

設計選擇：沿用 faster-whisper 官方批次與既有音訊重用、OOM 逐級回退，不換模型、不關閉單字時間對齊、不自行拼接切段。只在啟用批次時，於既有分行／繁體等後處理前檢查原始段落；異常整份回退標準辨識，保留原有安全發布。與直接更換 WhisperX 相比，避免新增模型與封裝風險。

## 工作與驗證

- [x] 先補重現測試：非法／倒退／超界時間、缺少單字對齊、低信心及高重複率；CPU 與 CUDA 相同流程。確認原本標準模式不受影響、異常不發布、取消不重試、品質回退不污染 OOM 快取上限。
- [x] 新增獨立 `batch_quality.py` 守門器，接入 `transcriber.py` 的批次消費端；不修改正常結果或標準推論。
- [x] 新增可重現的本機基準工具：固定參數、暖機、不同 batch／threads；參考文字字元錯誤率、段落與單字時間、已知語音區間覆蓋；結果只寫新報告。
- [x] CPU 使用既有 medium 真模型及合成中文測例；CUDA 無硬體時明確記錄未執行，不以模擬推論速度冒充實測。
- [x] 執行完整 Python（包含 GUI）回歸、網站測試與建置，獨立審查本次變更。

風險檢查：沉默不應視為失敗；錯誤時間不應被截斷後冒充正確；低品質不應被記成所有影片的批次記憶體上限；取消不能導致額外完整重跑；既有字幕不可覆寫。

品質門檻僅能偵測異常，不是辨識正確率保證；標準回退依舊需要校對。基準比較必須保留實際模式及回退原因，不將標準回退算作批次加速。

## 執行記錄

- 守門器實作前，CPU／CUDA 六個異常回退案例失敗；新增模組後通過。未啟用批次的標準流程仍原樣使用。
- 新增基準報告序列化回歸：NumPy 布林無法 JSON 序列化，重現後轉為 Python bool；已通過。
- 獨立審查指出標準與批次預設 VAD 不同，初版基準未對齊正式程式 500 ms。捨棄該次數據，以 CLI 行為測試重現後修正並重跑；無其他可操作 runtime 問題。
- 長合成測例沿用相同語音重複四次；每段的參考文字、定位點時間都重新映射，測試確認不會錯配到第一次出現的標記。不能當成真實長課程。
- 批次相關 31 個測試已通過，完整回歸與原生基準結果另記在 `BATCH_INFERENCE.zh-TW.md`。
- 基準工具每批完成後釋放 pipeline；弱參照測試重現並修正跨執行緒設定持有前一個模型的問題。8 執行緒在獨立程序重跑，不採混合模型的舊數據。
- 範圍判斷：本機無 NVIDIA，不使用 CPU 替代後冒稱 CUDA；不推送測試分支、不建立雲端 GPU 工作或發布版本。成本是 CUDA 效能及硬體相容性仍待 NVIDIA 實機驗證。
- 最終驗證：`VTS_RUN_GUI_TESTS=1 ... python -m unittest discover -s tests`，284 項中 278 通過、6 略過，65.047 秒。網站 22 項通過、建置成功，`git diff --check` 通過。未推送、未發布；版本不變。
