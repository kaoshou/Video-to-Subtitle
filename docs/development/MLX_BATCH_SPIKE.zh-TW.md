# MLX 批次轉錄試驗（未整合正式功能）

目的：使用既有本機 MLX Whisper 模型，檢查真正的批次解碼在包含 VAD、逐字對齊及時間軸還原後是否有收益。這是使用者同意試作的獨立 spike，不是正式字幕輸出器。

## 試驗範圍

- `scripts/spike_mlx_batch.py` 不被 GUI 或正式轉錄核心引用。
- 只接受既有本機模型目錄；不下載模型、不上傳影音、不變更模型快取。
- 以 Silero VAD 尋找語音範圍，長語音上限 28 秒，優先依停頓切段；無停頓時仍可能強制切開，不能保證不切斷句子。
- 合併相鄰範圍至最長 30 秒，保留範圍內的原始靜音，不拼接刪除時間。
- 同一模型、同一語言，以官方 `decode` 執行批次 1／2／4；使用時間戳解碼，再以官方 `add_word_timestamps` 逐段對齊。
- 每段與逐字時間加回原影片偏移，檢查時間合法、順序及影片上限。
- 低信心、重複異常、時間戳不完整或時間檢查失敗，該段退回原生轉錄。記憶體錯誤可退回整組原生流程；不具備正式功能的取消、完整 OOM 分級重試等機制。
- 首次非計時暖機包含原生逐字對齊；計時包含 VAD、辨識、對齊、回退及同步，不含檔案解碼與模型載入。
- 以完整原生轉錄作比較；文字相似度不等於正確率，也不代表對齊品質。

## 重現

```sh
python scripts/spike_mlx_batch.py --audio <合成測試音訊> --snapshot <本機MLX模型目錄> --report <新的JSON報告路徑> --repeat 4
```

`--repeat` 僅供重複合成音訊製造較長測例，不代表真實長課程。報告保留完整原生及試驗逐字時間，方便後續人工比對。尚不支援翻譯、提示詞、自動語言、正式字幕分行或 UI 整合；不可用此試驗直接取代既有流程。

## 2026-10-29 本機結果

使用既有 `mlx-whisper 0.4.3`／MLX `medium`，合成中文語音 38.03 秒重複四次，各次加一秒靜音，總長 156.12 秒。VAD 得到七段；以下均包含逐字對齊，且為暖機後測量。

| 流程 | 秒數 | 原生速度／此流程速度 |
| --- | ---: | ---: |
| 原生完整轉錄 | 14.657 | 1.000 |
| VAD 切段，批次 1 | 15.901 | 0.922 |
| VAD 切段，批次 2 | 14.546 | 1.008 |
| VAD 切段，批次 4 | 18.392 | 0.797 |

三種批次均無原生回退、時間檢查通過；相對原生文字的去符號字元相似度皆為 97.48%。這不是辨識正確率，也不是完整字幕等價證明。切段改變辨識結果，即使沒有字數異常也不能宣稱不漏字。

原始報告在本機 `/private/tmp/vts-mlx-spike-final-156s.json`，包含完整逐字資料；未加入版本控制。初版過度保守地將高無語音機率當成回退條件，但官方在平均信心高時不依此略過語音；已修正並整輪重新測量，表格採修正後數據。

額外檢查：真實 VAD 空白音訊返回空範圍、逐字與段落偏移還原、原始結果不被修改、非法／倒退時間被拒絕。

結論：目前這個完整方案沒有足以值得承擔行為差異的加速收益，暫不整合 GUI 或正式 `transcriber.py`。批次 4 更慢；不能由底層 decode 的短測例推估完整字幕效能。後續若繼續，需要對更長的真實課程評估，也可另行研究對齊實作，而非預設關閉逐字時間來美化效能數據。
