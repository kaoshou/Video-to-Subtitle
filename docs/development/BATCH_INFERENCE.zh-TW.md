# 音訊批次推論實作與本機驗證

## 實作選擇

進階設定提供預設關閉的「批次加速（試用）」，大小 2／4／8／16／32，預設 4；只有啟用且使用 CPU／CUDA 與 VAD 時可編輯。未啟用維持原有標準路徑。使用者關閉 VAD 或後端缺少批次介面時改走標準推論，日誌記錄原因。

採 faster-whisper 官方 `BatchedInferencePipeline`，保持 beam size 5、原有前導提示、熱詞、精準時間軸與輸出後處理。批次模式明確要求時間戳，不依賴與標準模式不同的預設值。其信心門檻與溫度重試行為仍與標準模式不同，因此不宣稱內容完全等同。

每個嘗試使用獨立暫存字幕；記憶體不足時縮小批次，最後退回真正的標準 `WhisperModel.transcribe`，不以批次大小 1 代替。成功後透過 `SafeDirectory` 排他發布，既有檔案另行編號，不覆寫。取消檢查涵蓋開始前、每個辨識段落、完成辨識後與最終原子發布前（含檔案占用重試），失敗嘗試不發布。原子發布完成後才收到的取消不撤回已完成輸出。

此功能不能強制立即中止正在執行的原生運算；必須等目前音訊準備／批次推論返回。批次大小也不代表整支影片的 RAM 上限，上游會事先解碼並準備特徵。

CPU 執行緒現在於模型載入前傳入；設定改變時重新建立核心。批次與 CPU 執行緒設定保存在既有使用者設定檔。

### 保守效能優化

`PreparedAudio` 在單一批次任務內重用相同 16 kHz 解碼波形，回退標準辨識時也可沿用。64 MiB 以內保留原始陣列，大於門檻則以私人 `.npy` 暫存搭配唯讀 NumPy memory map；離開任務關閉映射並清理，不建立永久課程快取。解碼或磁碟暫存不可用時回到原有檔案輸入；不快取特徵或辨識結果，也不更動辨識參數。

同一核心曾因 OOM 縮小後成功，才記錄工作階段上限，鍵包含模型實例、後端、精度、模型、任務、單字時間戳、前導提示及熱詞。使用者手動較小值優先；模型／設定不同不共用。取消或失敗不記住未完成結果。記錄不跨程式執行，也不自行往更大批次試探。

MLX 在進入原生轉錄前以公開的 `mx.array`／`mx.eval` 準備波形，避免原生轉錄函式在長時間推論時同時保留呼叫端 NumPy 波形；不更動取樣、精度、模型、時間戳或解碼流程。模型重用沿用上游 ModelHolder，不以切換注意力實作、量化或關閉時間對齊換取速度。

新增優化後以相同 medium MLX 模型、相同合成音訊比對，全文與完整段落／單字時間戳資料完全相等；原生弱參照檢查確認準備完成後可釋放原 NumPy 波形。約 38 秒音訊的優化後原生推論約 4.88 秒，短音訊未見明顯速度提升，主要改善長音訊記憶體保留。完整 GUI 回歸測試 267 項，261 通過、6 依條件略過；網站 22 項通過並完成建置，獨立審查無新增可操作問題。

## MLX 研究與處理

查核並實測 `mlx-whisper 0.4.3`：高階 `transcribe` 沒有 `batch_size` 參數。底層解碼可接受批次張量，但完整轉錄仍逐視窗處理；若要自行整合，需要另外處理 VAD 切片、每段語言／提示、低信心重試、時間戳映射及單字對齊，不能直接傳入 faster-whisper 的批次參數。

本次保留 MLX 原生加速，停用其批次大小選單並顯示原因；若從設定檔或程式介面要求批次，也明確記錄回退。沒有額外同時載入多份模型。修正原有單字時間戳未傳入、未保留的問題，讓精準時間軸可實際參與斷句；已載入的 MLX 模型不重複走模型下載／載入準備。

## 2026-10-29 本機驗證

使用 macOS 合成繁體中文語音，未使用或上傳使用者課程。相同測試音訊、CPU 4 執行緒、INT8、精準時間軸開啟；同一模型依序執行標準、批次 2、批次 4。這是單次開發測試，未控制所有快取／負載因素，不能視為通用效能承諾。

| 模型 | 標準 | 批次 2 | 批次 4 |
| --- | --- | --- | --- |
| tiny | 2.348 秒 | 1.406 秒 | 1.303 秒 |
| medium | 24.471 秒 | 18.373 秒 | 18.356 秒 |

medium 標準輸出 15 段、批次輸出 17 段；去除標點空白後均為 149 字，彼此文字相似度約 98.7%。這不是對照人工稿的辨識正確率；tiny 的差異較大，說明仍應逐案比較品質。

Apple MLX 使用既有 medium 模型實際辨識成功，標準與要求批次回退的測試各產出 16 段並通過時間軸檢查。第一次包含模型載入約 22.8 秒，後續原生快取約 5 秒；此差異不是批次加速，沒有以此宣稱 MLX 批次效能。

實際測到 faster-whisper 1.2.1 呼叫 PyAV 19.0.2 時因移除 `metadata_errors` 參數而失敗；以 PyAV 16.1.0 重測成功。專案依賴與三個安裝依賴的工作流程統一限制 `av>=11,<17`，避免新建環境重現。

`tests/test_batch_inference.py` 以替代辨識器測試途中／初始化記憶體不足、回退、取消（含最終 fsync）、不覆寫、五種格式、時間軸、MLX 選項與 VAD 關閉。原生 GUI 測試涵蓋選單啟用條件、保存還原及 CPU 執行緒重新初始化。

可用 `scripts/smoke_batch_inference.py --audio <測試音訊> --snapshot <本機模型快照> --device cpu|cuda|mlx --report <JSON>` 重現真實核心檢查。快照只讀、輸出在獨立暫存目錄，不需上傳影音。首次測試可能包含模型暖機，報告明確標記實際模式。

本機沒有 NVIDIA CUDA GPU；CUDA 執行效能、長達兩小時的課程品質、低顯示記憶體設備仍需對應硬體驗證。本次沒有推送或發布。

## CPU／CUDA 品質守門與進一步驗證（2026-10-29）

`batch_quality.py` 僅接入 CPU／CUDA 批次消費端。段落／單字時間為負數、非有限值、倒退／異常重疊、超出影片範圍，缺少使用者要求的單字對齊，或平均對數機率低於 -1／壓縮率高於 2.4 時，整份暫存捨棄並重新走標準辨識。容許小幅時間捨入差異，不截斷或修補時間來掩蓋異常。

品質回退不會被記成模型的記憶體批次上限；取消時不再開始標準重跑。保持既有解碼重用、OOM 降級與安全排他發布。不變更未勾選批次的標準推論、模型、beam size、前導提示、繁體後處理或 MLX。

### 原生 CPU 比較

使用 `medium` 本機模型、CPU INT8、4 執行緒、beam 5、逐字時間開啟、前文關聯關閉、VAD 500 ms。先暖機，57.21 秒測例跑正向／反向兩輪取中位數；228.84 秒測例跑一輪。秒數包含 VAD、推論及逐字對齊，不包含模型載入、檔案解碼及應用程式後處理。

測例為本機合成中文教學，含三段已知文字及六秒停頓；長測例重複四次並重建參考文字／時間，不是真實長課程或噪音環境。基準固定與正式程式相同的 VAD 參數，不混用上游標準 2000 ms／批次 160 ms 的預設值。

| 音訊 | 標準 | 批次 2 | 批次 4 | 批次 8 |
| --- | ---: | ---: | ---: | ---: |
| 57.21 秒，兩輪中位數 | 18.054 秒 | 17.123 秒 | 17.272 秒 | 17.339 秒 |
| 228.84 秒，一輪 | 54.115 秒 | 53.205 秒 | 50.001 秒 | 47.455 秒 |

短測例各模式的參考稿 CER 都是 5.19%，但實際文字仍有三個字的差異，不是完全一致。長測例標準 CER 3.89%，批次 2／4／8 都是 4.26%；代表兩個額外字元錯誤，不能宣稱沒有品質差異。CER 以繁簡正規化、去標點後比對已知合成稿，不以模型對模型相似度冒充正確率。

所有測例段落／單字時間檢查通過，短測例三個、長測例十二個標記均位於其已知語音區間；沒有單字中心落入已知靜音區域。這不是逐字起迄點的人工精度標註，不能由此宣稱每個字的時間完全準確。保持批次預設關閉及人工校對要求；不依單台 Mac 的結果變更所有 Windows 使用者設定。

### 重現工具與 CUDA 邊界

```sh
python scripts/benchmark_batch_quality.py --snapshot <本機模型目錄> --device cpu --threads 4 --batches 2 4 8 --repeats 2 --audio <合成WAV> --reference <參考JSON> --report <新報告JSON>
```

macOS 不提供 `--audio`／`--reference` 時會以 `say` 生成獨立合成測例；`--fixture-dir <新資料夾>` 可保留 WAV 與參考稿，以同一測例帶到 Windows／CUDA 比較。`--repeat-input 4` 用於增加測例長度。輸出只寫新路徑，不覆蓋現有報告。

CUDA 使用相同命令改成 `--device cuda`，不得將 CPU 代測冒充 CUDA。此機實測 CUDA 裝置不存在，工具以明確錯誤結束；CUDA 的記憶體不足、品質回退、取消及安全輸出為流程測試，非 NVIDIA 效能／硬體驗證。

原始合成測例及完整逐字報告留在本機 `/private/tmp/vts-cpu-cuda-fixture-20261029`、`/private/tmp/vts-cpu-batch-quality-20261029.json` 與 `/private/tmp/vts-cpu-batch-quality-long-20261029.json`，未上傳影音或模型。

### 執行緒與正式輸出

同一 57.21 秒測例另測 2／8 執行緒（各一輪）。2 執行緒標準 24.674 秒、批次 4 為 23.663 秒；8 執行緒以獨立程序重測，標準 19.859 秒、批次 4 為 19.132 秒。4 執行緒較合適，但不以這台設備的結果替使用者自動改設定。各模式 CER 5.19%，定位點／靜音區檢查皆通過。

基準工具新增模型釋放檢查：每批結果讀取完成即釋放該 pipeline，避免比較下一個執行緒設定時仍保留前一份模型。弱參照回歸測試先重現保留問題，再驗證修正；8 執行緒採獨立程序新報告 `/private/tmp/vts-cpu-batch-threads8-clean-20261029.json`，不採用初次混合模型的數據。
