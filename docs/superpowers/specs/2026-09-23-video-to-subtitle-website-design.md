# Video to Subtitle 官方網站與完整繁中手冊設計

## 目標

在既有 `kaoshou/Video-to-Subtitle` 儲存庫中建立繁體中文官方網站，發布至 GitHub Pages 專案網址 `https://kaoshou.github.io/Video-to-Subtitle/`。首頁應讓第一次接觸本工具的使用者快速理解用途、下載最新版並完成第一次字幕轉錄；另提供獨立的完整使用手冊，詳細說明 v2.7.7 現有功能、平台差異及疑難排解。

成功標準如下：

- 網站全程使用繁體中文，不顯示語言選擇頁。
- 首頁提供明確價值主張、最新版下載、三步快速上手、主要功能、真實介面截圖、平台資訊及完整手冊入口。
- `/Video-to-Subtitle/guide/` 提供可直接閱讀、可由目錄跳轉的完整手冊。
- 手冊內容依 v2.7.7 程式碼、介面文字、截圖及版本紀錄核對，不直接把目前 README 當成完整手冊。
- 網站可在桌面與行動裝置正常閱讀，無須第三方服務或瀏覽器端框架。
- GitHub Pages 自動部署與既有桌面程式建置／Release 工作流程彼此隔離。
- 網站與文件變更不會建立新的桌面程式 Release。

## 現況與內容稽核

目前儲存庫沒有網站來源、GitHub Pages 工作流程或獨立使用手冊。README 包含專案介紹、v2.7.0 至 v2.7.7 更新紀錄、功能摘要、基本使用流程、模型快取位置及開發者建置方式，但仍不足以作為完整使用手冊。

已確認需要修正或補足的部分：

- 一般使用者安裝說明只完整描述 Windows，缺少 macOS DMG 安裝與首次開啟流程。
- README 仍要求 macOS 使用者安裝 FFmpeg 與 `mlx-whisper`；v2.7.7 發行包已整合 PyAV 音訊解碼及 MLX 相關元件，一般使用者不應執行這些開發者安裝步驟。
- 主畫面的模型、運算單元、輸出格式、前導提示、熱詞與進階設定需要逐項說明。
- 字幕校對器的影音同步預覽、CC 疊字、播放速度、音量、搜尋、時間調整、分割與合併快捷鍵等內容尚未形成完整操作流程。
- 模型預先下載、快取狀態、儲存位置變更、快取清除、離線使用與常見下載錯誤需要獨立章節。
- EverCam 專案偵測、字幕產生、單一／批次網頁轉換及原始首頁備份機制需要完整說明。
- 一般使用者安裝與從原始碼執行必須分開，避免把 Python 套件或開發工具誤寫成安裝包的必要條件。

## 方案選擇

採用與 OpenCam 官方網站相同概念的輕量靜態網站產生方式，但只保留繁體中文路由並建立 Video to Subtitle 自有的內容與視覺識別。

選用小型 Node.js 建置程式、`markdown-it`、語意化 HTML、單一 CSS 與極少量 JavaScript。建置程式會從儲存庫內的 Markdown 手冊產生 HTML、複製核准的真實截圖與圖示，最後驗證所有路由和站內資產。

未採用的方案：

- 直接維護兩份純 HTML：雖然起始成本較低，但網站手冊與 Markdown 文件容易不同步。
- Astro、Vite 或其他前端框架：目前只有首頁與手冊兩種頁型，額外框架、依賴與升級成本沒有足夠收益。

## 資訊架構

網站提供兩個公開頁面：

- `/Video-to-Subtitle/`：繁中首頁。
- `/Video-to-Subtitle/guide/`：完整繁中手冊。

所有頁面共用固定導覽列，包含品牌首頁、完整手冊、GitHub 與下載入口。頁尾提供 GitHub、Releases、完整手冊及開發者資訊。首頁與手冊均使用專案站台根路徑安全的絕對網址，避免 GitHub Pages 子路徑部署時遺失樣式或圖片。

## 首頁內容

首頁以「影片留在電腦，字幕安心生成」為核心訊息，強調本機轉錄、隱私、免費與低操作門檻。首屏放置真實主介面截圖及兩個主要動作：「下載最新版」連至 GitHub Releases latest，「閱讀完整手冊」連至站內手冊。

首屏之後依序提供：

1. 三步快速上手：加入影音、選擇模型與輸出、產生並校對字幕。
2. 核心功能：本機 Whisper 轉錄、批次處理、台灣繁體轉換、前導提示與熱詞、內建字幕校對、模型管理及 EverCam 整合。
3. 真實介面展示：主操作介面、字幕編輯器與模型管理視窗。圖片具有具體替代文字及說明。
4. Windows 與 macOS 平台入口：說明對應發行檔，下載動作仍統一導向官方 Releases，避免網站硬編版本號或資產檔名。
5. 完整手冊導引：說明手冊涵蓋安裝、模型、校對、EverCam 與排解資訊。

視覺上沿用 OpenCam 網站清楚、留白充足、以產品截圖為主的結構，但使用 Video to Subtitle 介面的藍色作為品牌主色，搭配深墨藍文字與低彩度淺藍背景，不直接複製 OpenCam 的綠色識別。網站不載入 Google Fonts、分析碼或外部 UI 套件，以系統中文字型確保速度與隱私。

## 完整手冊

`docs/USER_GUIDE.zh-TW.md` 是完整手冊的唯一內容來源。它同時可直接在 GitHub 閱讀，並由網站建置程式轉換成 `/guide/` HTML。HTML 頁面會由二、三級標題產生側邊目錄，行動裝置上改為頁首可閱讀目錄。

手冊至少包含：

1. 工具用途、隱私模式與字幕需人工校對的提醒。
2. 系統需求與最新版下載。
3. Windows 執行方式，以及 macOS DMG 安裝與首次開啟方式。
4. 第一次啟動與 Whisper 模型下載。
5. 三步基本轉錄流程與支援的影音格式。
6. 模型大小、速度、準確度、磁碟用量及建議使用情境。
7. Windows CPU／CUDA 與 macOS CPU／MLX 的差異；把 CUDA 等額外設定清楚標為選用功能。
8. SRT、VTT、TXT、TSV、JSON 輸出用途。
9. 強制繁體中文、翻譯英文、前導提示、熱詞匯入與進階斷句設定。
10. 多檔案批次處理、取消任務與完成後檔案管理。
11. 字幕校對器、影音預覽、搜尋、時間軸調整、CC、播放速度、音量、分割／合併及保存。
12. 模型儲存管理、預先下載、搬移路徑、快取清除及離線使用。
13. EverCam 課程辨識、轉錄、播放器轉換、批次處理與備份行為。
14. 更新檢查與版本資訊。
15. 網路、模型快取、磁碟空間、權限、CUDA、MLX 及影音播放等常見問題。
16. 從原始碼執行與打包；此章明確標示為開發者內容。

內容撰寫以實際程式行為為準。若 README、舊版本紀錄與 v2.7.7 程式碼不一致，手冊採用目前程式碼與發行包行為；無法從專案證明的系統需求或效能數字不寫成保證。

## README 調整

README 保留專案介紹、版本紀錄與開發者資訊，不在本次工作中全面重寫。新增官方網站和完整繁中手冊的醒目入口，並修正一般 macOS 使用者需自行安裝 FFmpeg／`mlx-whisper` 的過時說法。原始碼執行章節仍可保留這些開發相依套件，但會與發行版使用方式清楚分開。

## 建置結構

新增 `website/` 目錄，包含：

- `package.json` 與鎖定檔：固定 Node 版本範圍與 Markdown 轉換依賴。
- `build.mjs`：讀取內容、產生靜態路由、複製圖片與執行輸出驗證。
- `src/`：路徑工具、共用版型、首頁內容、Markdown 手冊轉換、CSS 與必要 JavaScript。
- `tests/`：使用 Node 內建測試執行器驗證輸出。
- `dist/`：本機與 CI 產生的發布成品，不作為人工維護來源。

JavaScript 只用於漸進增強，例如行動版導覽或目錄互動；沒有 JavaScript 時首頁、下載、導覽及完整手冊仍可使用。

## GitHub Pages 與 Release 隔離

新增獨立的 `.github/workflows/deploy-pages.yml`：

- 在 `main` 分支的網站來源、手冊、網站使用圖片或工作流程變更時執行。
- Pull request 只建置與測試，不發布。
- `main` 分支建置成功後，上傳 `website/dist` 並以 GitHub Pages 官方 Actions 發布。
- 部署工作只授予 `contents: read`、`pages: write` 與 `id-token: write` 所需權限。
- 使用 `github-pages` environment 回報實際網址。

目前 `.github/workflows/python-app.yml` 對每次 `main` push 都建置並建立 Release。這會造成網站提交也觸發桌面程式發布，因此本次會為該工作流程加入精確的產品來源路徑條件。網站、文件與 Pages 工作流程變更不應觸發桌面建置；桌面程式碼、套件設定、圖示、打包規格或桌面建置工作流程變更仍維持原行為。`workflow_dispatch` 保留供手動發布使用。

若儲存庫尚未把 Pages Source 設為 GitHub Actions，推送後需透過 GitHub API 或設定頁啟用。若目前憑證無權限修改此設定，應回報需要的人工設定，不可在未確認成功時宣稱網站已上線。

## 測試與驗收

自動測試涵蓋：

- 首頁與手冊路由正確產生，並以 `/Video-to-Subtitle/` 為站台根路徑。
- 每頁只有一個主要內容區，圖片皆具替代文字。
- 所有站內連結與靜態資產可解析，缺少必要截圖時建置失敗。
- 首頁含最新版下載、快速上手、三張真實截圖及完整手冊入口。
- 手冊保留所有必要主題，且不含已知過時的一般 macOS 安裝指示。
- Markdown 中的程式碼或 HTML 不會變成可執行腳本。
- Pages 工作流程只發布靜態輸出，且與 Release 流程分離。
- 桌面 Release 工作流程不會因純網站／文件變更而啟動。

實作完成後執行網站測試與正式建置，再以本機伺服器檢查首頁和手冊的桌面及窄螢幕版面、中文換行、圖片比例、導覽、焦點狀態與目錄捲動。推送後檢查 GitHub Actions 部署結果並開啟實際 Pages 網址；只有在實際網址可載入後才回報已發布。

## 範圍界線

本次不修改桌面應用程式功能、不重新設計程式介面、不建立英文網站、不加入分析追蹤、不建立自訂網域，也不把 GitHub Release 檔案複製到 Pages。網站所有下載連結指向官方 GitHub Releases，以維持單一可信發布來源。
