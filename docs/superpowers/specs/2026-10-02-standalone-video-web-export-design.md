# 一般影片＋字幕匯出網頁：功能設計規格

日期：2026-10-02

狀態：功能方向已確認；本書面規格待使用者審閱。尚未授權實作或發佈。

基準：目前 v2.7.8 播放器、EverCam 整合與安全檔案操作。

## 1. 目的與範圍

讓沒有 EverCam 專案的使用者，以一支 MP4 與一組 SRT／VTT 字幕，建立可本機開啟、也可上傳靜態網站的現代化播放器網頁。只需確認影片、字幕、標題、輸出位置即可匯出；作者、單位、簡介、封面等資料由使用者選填，不自動臆測。

首版包含：

- 單支 MP4、多語字幕切換、可設定初始字幕或關閉字幕。
- 基本資訊設定、無章節時的單欄播放器。
- 影片、字幕、封面與播放器資源的完整複製匯出。
- 保留設定，重新載入已匯出的資料夾、修改資料，再匯出新的資料夾。
- 原始檔不變更、可取消、大檔案串流複製與既有符號連結安全防護。

首版不包含：多影片課程入口、批次一般影片匯出、自動／手動章節編輯、AI 標題或摘要、影片重新編碼、上傳代管、單一 HTML 內嵌影片、同時顯示兩種語言字幕。多語指切換字幕軌，不承諾新增雙語並列功能。

## 2. 現有程式依據與方案選擇

- `SubtitleTranscriber.py` 的 `EverCamConverterDialog` 已有既有課程轉換流程；完成轉錄的視窗已有影片與結果檔脈絡。
- `evercam_integration.py` 的 `is_evercam_folder()` 以 `config.js` 加影片判斷 EverCam；一般匯出若沿用此檔名會產生誤判。
- `assets/evercam_player/js/evercam-modern.js` 已讀取標題、作者、影片來源、封面、章節及字幕；作者空白時會隱藏。沒有章節時，目前仍保留章節側欄。
- `assets/evercam_player/index.html` 以 script 載入設定及字幕資料，不依賴 fetch 讀取本機 JSON。
- `safe_files.py` 已提供 no-follow、Windows reparse-point 檢查及安全替換，但目前以完整 bytes 讀寫，不能直接用於大型影片。

選擇「新增一般影片匯出模組，共用播放器及安全工具」。相較於另外維護一套播放器，可保持控制列、字幕樣式與安全修正一致；代價是共用播放器的變更必須同時驗證 EverCam 模式。一般匯出不偽装成 EverCam，不放寬既有辨識條件，不调用 EverCam 的原地部署／首頁備份流程。

## 3. 桌面操作流程

### 3.1 入口

主畫面原「EverCam 網頁轉換」入口改為「網頁播放器」，提供明確選擇：

1. 「EverCam 課程轉換」：開啟原有對話框，保留單筆、批次、掃描與原首頁備份行為。
2. 「一般影片＋字幕」：開啟新的匯出對話框。

轉錄完成視窗對有對應 MP4 及 SRT／VTT 的結果增加「匯出字幕網頁」，帶入確定配對的影片及字幕。不是 MP4 或僅有 TXT 的結果不提供誤導性捷徑。多個結果按各列分別開啟，不在首版自動批次匯出。

### 3.2 一般影片匯出對話框

預設顯示：

- 影片選擇及檔名、檔案大小、可取得的影片長度。
- 字幕清單：檔案、語言、移除；「加入字幕」允許多筆。
- 網頁標題。
- 輸出父資料夾與新資料夾名称；顯示完整最終位置。
- 可展開的「更多網頁設定」。
- 「載入已匯出的網頁」「匯出」「關閉」；工作中提供「取消」。

匯出前驗證所有欄位，列出錯誤所屬檔案／欄位；不逐一彈出大量訊息視窗。驗證成功後顯示要複製的總大小及目標位置。匯出執行於背景工作，GUI 透過主執行緒更新進度，不阻塞視窗。

成功後顯示「開啟網頁」「開啟輸出資料夾」；不自動上傳。只有在整包通過驗證後才提供成功預覽。

### 3.3 欄位規則

| 欄位 | 初始值與行為 | 驗證 |
|---|---|---|
| 影片 | 手選；完成視窗則帶入已知來源 | 一般可讀檔案、MP4 容器且含可辨識影片軌 |
| 字幕 | 完成視窗帶入已知結果；其他情況列出同目錄同檔名候選供確認 | 至少一軌，SRT／VTT，UTF-8 或 UTF-8 BOM；不能直接使用 TXT |
| 網頁標題 | 影片 basename 去除最後副檔名；保留原有中文與標點 | 去除首尾空白後必填，最多 200 字元 |
| 講者／作者 | 空白 | 選填，最多 100 字元；空白隱藏 |
| 單位／課程名稱 | 空白 | 選填，最多 200 字元；空白隱藏 |
| 內容簡介 | 空白 | 選填，多行純文字，最多 5,000 字元；不解析 HTML／Markdown |
| 封面 | 未設定 | 選填本機 PNG／JPEG；須能解碼，最多 20 MiB／2,500 萬像素，不接受 SVG、URL |
| 字幕語言 | 轉錄設定或檔名可可靠辨識時提出候選 | 不可靠時顯示「請選擇語言」；每軌必須確認有效語言碼，同語言重複須移除或更正 |
| 預設字幕 | 第一條確認加入的字幕 | 可選其他字幕或「關閉」；移除選中軌後重新要求確認 |
| 影片長度 | 讀取媒體資訊，播放時以瀏覽器 metadata 為準 | 不開放手填；無法取得時不編造時長 |

字元上限均為 Unicode 字元數，不以 UTF-8 bytes 或畫面寬度計算。未知欄位不套用開發者名稱、檔案日期等無關預設值。

標題採 dirty-state：尚未手動修改時，換影片可更新自動標題；手動修改或從既有設定載入後，不再因換影片／字幕而覆寫。提供「使用影片檔名」可明確恢復自動標題。

顯示標題與輸出資料夾名稱分開儲存。輸出名稱可由標題提出合法候選，但之後不連動；不允許路徑分隔符、`..`、Windows 保留名稱、ADS 或尾端空白／句點。預設建議 `<影片名稱>-web`，冲突時建議帶序號的新名稱，仍須在建立時排他確認。

## 4. 輸入與相容性檢查

- 自動搜尋只提出候選，不能任意選取多個候選中的第一個，也不能把另一支影片的字幕靜默配入。
- 字幕解析保留原有文字與時間軸；不新增校正、翻譯或重新轉錄。辨識出的註解／WebVTT 非字幕區塊按格式處理。
- 拒絕完全沒有有效 cue、非有限或負數時間、結束早於或等於開始、無法解析的字幕時間區塊；提供檔名與可定位的錯誤。合法重疊字幕不因重疊就被拒絕；超出影片時長的字幕顯示警告，由使用者確認或返回修正，不自動截斷。
- 既有 EverCam 輸入的容錯行為不因新匯出器的較嚴格驗證而改變；需要共用解析器時，以額外驗證層或兼容介面隔離差異。
- 從媒體資訊提出瀏覽器相容性提示；MP4 副檔名或本機解碼成功不代表所有瀏覽器皆可播放。無法讀取／無影片軌是錯誤，不確定瀏覽器支援則是清楚警告。
- 不自動重新編碼或修改來源。已知測試媒體必須完成目標瀏覽器的實際播放驗證；不能只根據容器判定功能通過。

## 5. 網頁呈現與字幕選擇

一般影片匯出設定明確指定 `mode: standalone` 及 `index: []`。

- 沒有章節時隱藏整個章節卡片，播放器改為置中、具最大寬度的單欄；不留下空白欄或「尚無章節索引」。
- 此版面規則只在一般影片模式啟用；EverCam 的有／無索引呈現維持既有行為。
- 頁面及瀏覽器分頁採用使用者標題。作者與單位出現在標題下方；有內容才顯示。簡介在播放器下方，以純文字並保留換行呈現。
- 沒有封面就不設定 poster，不保證所有瀏覽器都會自動展示第一格影像。
- 保留既有播放、音量、倍速、字幕外觀、全螢幕、鍵盤操作；子母畫面仍以瀏覽器支援能力為準。
- 一般模式以獨立且持久的 package ID 儲存字幕偏好，避免同名影片互相覆蓋。初次使用套用匯出預設；之後若曾明確選擇且該軌仍存在，優先套用觀眾偏好；不存在則回退至匯出預設。無法使用 localStorage 時仍能播放。
- 重新匯出相同專案保留 package ID；全新匯出建立新 ID。EverCam 的既有偏好鍵保持兼容。

## 6. 匯出資料夾與設定契約

```text
第一週課程-web/
  index.html
  media.mp4
  player-config.js
  subtitles-data.js
  web-export.json
  poster.png 或 poster.jpg       # 有選封面才產生
  media.zh-TW.srt                # 範例：實際語言與副檔名依匯入來源
  media.en.vtt
  css/evercam-modern.css
  js/evercam-modern.js
```

所有資源以相對路徑使用；不把來源絕對路徑、使用者家目錄或原始檔案位置寫進可公開的資料包。影片用串流複製成 `media.mp4`，不重編碼。字幕保留原格式並規範化為 UTF-8 檔案；播放器讀取由工具生成的字幕資料。

`web-export.json` 是桌面工具重新編輯的純 JSON 清單：

- `schemaVersion: 1`、`kind: video-to-subtitle-web`、`packageId`、`appVersion`。
- `metadata`：`title`、`author`、`organization`、`description`。
- `video`：固定相對檔名 `media.mp4`、可選的探測時長。
- `poster`：空值或允許的固定封面檔名。
- `subtitles`：依序列出有效 `language`、包內相對檔名；`defaultSubtitle` 為語言碼或 `off`。
- 不儲存外部 URL、來源絕對路徑或先前輸出位置；載入後由使用者選擇新的輸出父資料夾。

`player-config.js` 是供本機網頁載入的生成檔，設定 `window.VTS_PLAYER_CONFIG`；不命名為 `config.js`。共用播放器優先讀取此一般模式設定，再兼容原有 `window.config`。一般版 HTML 載入 `player-config.js`，EverCam HTML 繼續載入 `config.js`。兩者使用同一份播放器 JS／CSS；頁面外框可有小型專用模板，避免大量複製邏輯。一般版模板不得放進 EverCam 的無差別資源複製目錄而被誤部署。

生成給播放器的設定將 `metadata` 展平成既有的 `title`、`author` 及新增的 `organization`、`description`，另包含 `mode`、`packageId`、`defaultSubtitle`、`index: []`；`src` 使用 `[{"src":"media.mp4","type":"video/mp4"}]`，`poster` 僅在有封面時設定。字幕仍使用既有 tracks／cues 資料結構。純 JSON 清單是重新編輯的資料來源，JS 設定是其生成結果，工具不反向解析或執行 JS 來載入設定。

一般匯出器不直接调用目前要求 EverCam 目錄的 `generate_subtitles_data_js()`；共用的是 cue 解析與資料序列化，不是假造 EverCam 檔案。既有 `window.EVERCAM_SUBTITLES` 資料契約可保留，避免為命名而改寫整套播放器。

字幕資料與設定由本機 script 載入，不以 `fetch(web-export.json)` 作為播放必要條件。可移動整個資料夾並以 `file://` 或 HTTP(S) 開啟，不依賴外部字型、CDN、帳號或伺服器 API。一般匯出不附帶 EverCam 專用「更新字幕.cmd」；後續更新統一由桌面匯出工具載入設定。

## 7. 再次修改既有網頁

「載入已匯出的網頁」選取資料夾，只讀取有大小限制的 `web-export.json`，不執行資料夾內的 HTML 或 JavaScript。

驗證 kind、schemaVersion、欄位型別、長度、語言及包內路徑；未知主要版本明確拒絕，不猜測轉換。首版只接受上節允許的根目錄單一檔名；拒絕絕對路徑、URL、`..`、分隔符與任何符號連結／reparse point。清單限制 1 MiB，避免無界讀取。

以包內複製的影片／字幕／封面回填，搬移資料夾後仍可編輯；缺失檔案顯示具體缺項，允許重新選擇來源，不自動連線下載。

首版的「更新」是另存新包，不就地覆寫：例如由 `第一週課程-web` 載入後，建議輸出 `第一週課程-web-2`。舊包繼續可用，不刪除使用者額外加入的檔案；新版僅包含受管理內容，不自動複製任意舊 JS／HTML 或不在清單中的自訂檔案，介面須明示此點。

## 8. 安全輸出、資源與取消

1. 先驗證全部欄位、來源檔案與可取得的媒體資訊，再檢查目的地。
2. 選定輸出父資料夾，最終子資料夾必須不存在；即使同名資料夾為空，也不直接覆寫。預估完整副本大小加上暫存／資源保留空間，空間不足先報錯。
3. 在同一父資料夾排他建立私有、唯一的 staging 目錄，使用既有安全路徑策略開啟來源及輸出；讀取來源時不跟隨連結。
4. 影片以固定大小區塊（建議 4 MiB）串流複製，累計 bytes 更新進度，每一區塊檢查取消。不要對大型影片调用現有全檔 `read_bytes()`／`write_bytes()`。
5. 安全工具新增受控串流讀寫能力時保留現有 bytes 介面與既有呼叫行為；POSIX 使用目錄描述元／no-follow，Windows 固定目錄 handle 並拒絕重新解析點。不能退回僅檢查 `islink()` 後普通 `open()`。
6. 複製前後檢查同一開啟來源檔案的大小與修改資訊，讀取量不一致或來源改變時中止並說明。此檢查不宣稱對具有相同 OS 權限的持續惡意修改提供完整隔離。
7. 生成設定、字幕資料、純 JSON 清單與受信任的播放器資源，驗證包內引用完整。
8. 關閉／flush 檔案後，以該平台支援的排他目錄發布方式把 staging 更名為最终名稱。目的地在工作途中出現時，失敗而不是覆盖。不得以「先 exists 檢查，再可覆寫 rename」取代此保證。
9. 不支援安全發布／rename 的檔案系統明確失敗，不採不安全降級；第一版需實測常見本機磁碟，外接／網路磁碟不能只靠推論宣稱支援。

一般模式的整包成功邊界是最終發布；完成前只存在 staging，不回報成功。不可把這项新保證套用到現有 EverCam 原地部署而宣稱其已具整包交易能力。

取消／失敗只清理本次建立、仍可驗證歸屬的 staging 與檔案，不遞迴刪除來源、輸出父目錄或任意已有路徑。若无法安全清理，保留該暫存並顯示位置；不誤報清理成功。程序崩潰留下的暫存不自動跨次刪除。最終發布前可取消；發布已成功則回報成功，不因稍晚到達的取消訊號刪除已完成資料包。

所有自由文字以資料序列化，DOM 使用 `textContent`，不得以 `innerHTML` 顯示輸入。HTML 模板的 title 等欄位須做相應跳脫；生成 JS 不手工串接未跳脫字串。封面須安全解碼檢查並重新輸出 PNG／JPEG，避免攜帶非必要中繼資料。提供 HTML／JS 特殊字元與惡意路徑測試。

## 9. 模組分工與既有功能保護

| 元件 | 責任 | 既有契約 |
|---|---|---|
| 桌面一般匯出對話框 | 選檔、欄位、候選確認、背景工作進度、取消與預覽 | 不混入 EverCam 課程清單／掃描邏輯 |
| 新增一般網頁匯出模組 | 資料驗證、媒體檢查、設定重載、匯出生命週期 | 不要求 EverCam config.js，不修改來源 |
| 共用字幕能力 | cue 解析與序列化 | 舊 EverCam 包裝函式與容錯保持兼容 |
| safe_files.py | 安全分塊 I/O、排他建立／發布 | 舊原子 bytes 儲存與備份語義不變 |
| 共用播放器 JS／CSS | 一般模式中繼資料、字幕預設、單欄版面 | 缺少新設定時維持 EverCam 模式 |
| 一般網頁 HTML 模板 | 載入 player-config.js、使用相同 DOM 控制元件 | 不取代／污染 EverCam 的 index.html 部署 |

此次不處理 TLS 更新、模型管理、辨識引擎、字幕校對器操作方式等無關項目。發佈版本號、commit／push／Release 另行確認，不由設計核准自動推導。

## 10. 驗收條件

### 功能

- 選 MP4＋SRT／VTT、確認預設標題即可匯出；中文、空白與特殊字元檔名可正常使用。
- 手動標題不被換字幕或換影片靜默覆寫；作者、單位、簡介空白時沒有空白標籤。
- 能加入繁中／英文字幕、切換及關閉；同語言冲突會阻擋；原始字幕時間與文字不被翻譯或改寫。
- 一般網頁無章節側欄、桌面與窄螢幕版面正常；原 EverCam 有章節及無章節案例與此前一致。
- 移動整包、在另一個位置重新載入設定、改標題／字幕並另存新包皆成功；舊包 bytes 不變。
- 一般輸出不會被 `is_evercam_folder()` 或既有批次掃描誤認成 EverCam。

### 安全與失敗情境

- 既有 symlink／懸空 link、Windows junction／reparse point、輸入與輸出切換競態，均不導致外部目標覆寫。
- 大型影片不整檔載入記憶體；取消、空間不足、讀取中斷、來源變更與目的地競爭案例有明確結果。
- staging 沒有完成不回報成功；清理只作用於本次擁有的資料；既有來源、原首頁及舊輸出不受損。
- 不執行匯入包中的 JS；拒絕清單穿越、絕對路徑、URL、畸形／過大設定與不支援版本。
- 標題、作者、簡介與字幕含 HTML／JS 片段時只顯示為文字，沒有程式執行或額外網路請求。

### 平台、瀏覽器與打包

- Windows 與 macOS 執行 Python 回歸測試，保留現有安全案例；新增字幕匯出、設定重載、取消及大檔分塊案例。
- Windows 的 Chrome／Edge、macOS 的 Safari／Chrome，以已知相容的短片分別實測 `file://` 與本機 HTTP：播放、字幕開關、切換、跳轉、全螢幕、持久偏好不可用時的降級。
- 確認打包成品包含新匯出模組與模板；在沒有開發環境的成品中完成一次匯出與預覽。
- 網站既有測試保持通過；實作完成後同步繁中手冊、入口名稱與新功能截圖，不提前宣稱功能已存在。
- 本規格只是驗收要求，並非上述測試已完成的聲明。缺少相關平台證據時列明缺口，不宣稱全面相容。

## 11. 實作前審閱重點

使用者已確認單影片、多語字幕、自訂基本資訊、無索引單欄、安全匯出與重新編輯的方向。本規格將「重新編輯」明確落定為另存新資料夾，並新增與 EverCam 隔離的設定檔名稱。請先確認這些細節；確認後才拆分實作計畫，不在此階段修改程式或發佈。
