# 選用 AI 工具連接（MCP）：功能設計規格

日期：2026-11-04

基準：v2.9.2，commit `050a6683693bfd1900c1e9aebbac5118aba3522d`。

狀態：使用者已同意「獨立背景 MCP、預設關閉、不必先開主視窗」架構。本文件是待使用者確認的設計，不代表已實作、已設定任何 AI 用戶端或已授權發布。

## 1. 使用者需求與方案選擇

### 1.1 使用者已確認

- MCP 是選用功能，使用者決定是否開啟，不影響一般轉錄。
- 操作簡單；除手動設定，提供功能入口、已安裝 AI 工具偵測及一鍵設定。
- 涵蓋 Codex 本機用戶端、Claude、Google Antigravity 等工具；不可把不同產品當成同一設定格式。
- 目標工作流：AI 呼叫本機工具轉錄 → AI 翻譯多語 → 回填字幕 → 匯出多語網頁播放器。
- 採獨立背景模式，使用時不必預先開啟字幕工具主視窗。

### 1.2 Approaches

| 方案 | 優點 | 取捨與結論 |
| --- | --- | --- |
| 獨立背景、本機 STDIO MCP | AI 按需啟動，主視窗可關閉，不需公開網路服務 | 需要獨立入口及跨進程任務協調；使用者已選擇 |
| 主視窗開啟時提供服務 | 背景生命週期較單純 | 忘記開啟即連不上，關閉時中斷使用；不採用 |
| 公開 HTTP／雲端 MCP | 可服務一般網頁端／遠端用戶端 | 額外暴露、登入與部署需求，不符合首版範圍；延後 |

### 1.3 本文件提出、待確認的預設

- 首版以 Windows x64、macOS arm64 為正式封裝平台，沿用三種 Release 成品名稱規則，不額外增加重複安裝檔。
- 模型未下載時回報 `MODEL_DOWNLOAD_REQUIRED`；AI 不自行下載或刪除模型。使用者先在原模型管理介面下載。
- 同一使用者一次只執行一個高負載轉錄；其他轉錄排隊，文字讀取與翻譯回填不因此全部阻塞。
- 首版直接修改的輸出只限新的 MCP 工作區及新的網頁包；EverCam／OpenCam 原地置入列第二階段。
- 新語言在全部段落完整且格式驗證成功後才產出正式字幕；標示「AI 翻譯，待人工校對」，不強迫每一段人工核可才可匯出。
- 工作紀錄保存在本機；關閉 GUI 不取消 MCP 任務。無工作且無連線時，背景程序閒置 5 分鐘後退出，仍可再次按需啟動。

## 2. 目標、非目標與現有程式依據

目標是給相容 AI 用戶端可組合的可靠工具，不是在桌面程式中新增聊天視窗。AI 負責語言推理；本機程式負責媒體處理、時間軸、資料驗證與安全發布。

現有可沿用的能力：

- `transcriber.SubtitleTranscriber`：CPU／CUDA／MLX、繁體轉換、批次推論、安全回退、進度及取消 callback。
- `web_export.py`：字幕解析、媒體驗證、共用 EverCam 播放器的新資料夾匯出。
- `web_export_form.py`：字幕候選及不覆寫的資料夾命名。
- `safe_files.py`：目錄控制代碼、符號連結／reparse point 防護、安全建立與替換。
- `opencam_integration.py`、`evercam_integration.py`：第二階段的受控整合，不從 MCP 重新解析並執行匯入 JavaScript。

必須解開的邊界：

- `SubtitleTranscriber.py` 入口頂層目前匯入 Tk；所有發行入口 `console=False`。不能把現有 Windows EXE 直接當 STDIO 伺服器。
- 核心有 `print`／第三方進度輸出；MCP STDOUT 必須只含協定訊息。
- GUI 與多個 AI 用戶端目前沒有跨進程 GPU／模型工作鎖；不能只在 MCP 進程各設一個鎖。
- 既有原生設定不可直接當成 AI 可修改的參數；MCP 採獨立、限制過的工作設定，不變更使用者的 GUI 偏好。

首版非目標：公開網路端點、遠端 GPU／Colab、任意執行命令、任意讀寫檔案、讀取 AI 聊天／憑證、自動安裝 AI 軟體、API 金鑰管理、訂閱或登入代辦、上傳教材、全面聊天整合、全機搜尋、任意中途續跑 Whisper 的內部解碼狀態。

## 3. 使用者介面與首次設定

入口名稱為「AI 工具連接」，標示 MCP；沿用原配色、字型及控件尺寸，不讓主畫面多出大面板。只在進入設定時執行偵測；一般啟動不掃描 AI 軟體。

預設畫面只顯示總開關、簡短資料流說明、教材資料夾、AI 工具列表及連線測試。命令、參數、設定路徑、記錄與診斷置於進階區。

首次流程：

1. 使用者開啟 MCP，閱讀「本機轉錄，雲端 AI 仍可能收到字幕」說明。
2. 選取一個或多個教材資料夾作為允許範圍；預設不選整個家目錄或系統根目錄。
3. 偵測安裝，使用者勾選要設定的 AI 工具，查看即將新增的本工具項目及存取範圍。
4. 按「設定連接」；先備份，再以對應適配器加入自己的設定。需要客戶端確認的流程導引使用者完成，不繞過。
5. 以封裝後入口執行本機 MCP handshake／工具列舉測試，不載入模型。
6. 如需客戶端重新載入，顯示「等待重新載入」，不自行關閉或重新啟動 AI 用戶端。
7. 提供可複製範例：「將教材資料夾中的這支影片轉成原文字幕，再翻成英文和越南文，完成後建立多語網頁播放器。」

每個用戶端分別顯示：未偵測到、已偵測、未設定、設定完成待重新載入、設定衝突、受政策限制。另顯示整體「本機協定測試成功／已收到實際 AI 連線」。沒有可信來源能證明用戶端身分時，不把其自報名稱當成已驗證的連線狀態。

提供手動選取程式／設定檔、複製設定、重新偵測、重新測試、修復自己的連接及移除自己的連接。未安裝仍可匯出設定，標示未驗證，不製造成功綠燈。

## 4. 用戶端適配器與可回復設定

### 4.1 支援策略

| 用戶端 | 首版適配方式與限制 |
| --- | --- |
| Codex 本機桌面／CLI／IDE | 按官方 TOML MCP 設定格式，處理設定根目錄覆寫；僅寫入本工具 server table，保留其他 TOML 內容與註解。不調整全域信任或審核設定 |
| Claude Code | 單獨識別 user／project scope，預設選使用者自己的範圍；依已驗證格式或官方管理入口操作。不混寫 Claude Desktop 設定 |
| Claude Desktop | 優先提供由程式產生的本機 `.mcpb` binary extension 安裝流程與必要的使用者確認；手動路線限已驗證版本。不把擴充套件安裝說成無需確認的靜默設定 |
| Antigravity | 依安裝版本、現有設定及官方 schema 選適配器；新舊路徑不盲目同時寫入。位置不明確時要求手動選取，不猜測成功 |
| Gemini CLI | 獨立 settings／MCP 管理適配器，不沿用 Antigravity 路徑。不使用略過工具確認的 trust 選項 |
| 其他／未知版本 | 產生命令、參數與 JSON／TOML 片段供手動連接；不對未知 schema 自動寫入 |

「支援設定」和「真實用戶端驗證通過」在文件分開標示。首版必須驗證 Windows／macOS 的 Codex 與 Claude 路線；Antigravity／Gemini 適配器未通過相對應實測版本時，只提供手動匯出，不宣稱已一鍵連通。

一般網頁聊天不讀取這些本機設定。ChatGPT 網頁、Gemini 網頁等不列為本機自動設定成功的目標；遠端方案另立設計。

### 4.2 偵測與寫入規則

- 僅查已知安裝位置、OS 應用程式中繼資料、選取用戶端的已知設定路徑及必要環境覆寫；不遞迴掃描磁碟、不讀取帳戶憑證或對話紀錄。
- 偵測不執行 PATH 中任意同名程式。需要官方 CLI 時，先解析並顯示實際程式路徑；使用 argv 陣列、不經 shell，不在偵測階段執行可變更狀態的命令。
- 使用者選擇設定後才讀取其設定內容；內容可能含第三方秘密，不回傳給 AI、不顯示完整內容、不記錄到日誌。
- 新項目使用固定命名空間 `video-to-subtitle`。同名但內容不同時要求確認修復，不自動接管未知項目；反覆設定具有冪等性。
- 限制設定檔大小、驗證 schema；遇到無法解析、組織管理或唯讀設定，停止並提供人工路線。
- 備份保存在本機使用者私有目錄，限制 POSIX 權限／Windows ACL；不放入教材輸出或傳至 MCP。備份可能含原有設定的秘密，須在說明中告知。
- 預覽與寫入間比較檔案版本，使用安全替換；如其他程式改動，重新讀取並提示衝突，不覆蓋新設定。
- 移除／回復只處理本程式登記且內容仍符合預期的那個項目，不拿整份舊備份覆蓋使用者之後的設定。
- 不自動新增全域信任、不關閉安全提示、不繞過組織政策，不修改登入帳戶或連接其他資料服務。

## 5. 背景架構與封裝

```text
相容 AI 用戶端
  └─ 本機 STDIO 薄入口（僅協定輸出，不載入模型）
       └─ 私有本機 IPC／共用任務協調器
            ├─ 轉錄工作（既有 CPU／CUDA／MLX 核心）
            ├─ 分頁逐字稿／翻譯草稿儲存
            └─ 驗證及網頁安全匯出

桌面主程式 ── 開關／權限／工作監看
            └─ 高負載工作鎖，與 MCP 任務使用相同協調機制
```

### 5.1 程序邊界

- 新增小型、可保留 STDIN／STDOUT 的專用啟動器；Windows 不以 `console=False` 的 GUI EXE 直接承載 STDIO 協定。
- 協調器／媒體 worker 為可無 GUI 啟動的獨立入口，可重用已封裝核心依賴；必須在 GUI 匯入／建立視窗前分流。背景啟動不彈終端或 Tk 視窗。
- 協定 STDOUT 僅 JSON-RPC；診斷進 STDERR／私有記錄。第三方的 print、progress、FFmpeg 輸出不污染協定通道。
- 使用同一 OS 使用者私有的 IPC，不新增 TCP 監聽埠：POSIX 使用私有 Unix socket 目錄，Windows 使用限制目前使用者 SID 的 named pipe。其他使用者不可連線；同帳戶惡意程式不在隔離保證內。
- 不把 MCP client name、connection identity、工具 annotation 或請求傳入的路徑當成授權依據。授權由 GUI 所保存的政策及伺服器驗證決定。
- 原生 GUI 與 MCP 共用跨進程高負載鎖；首版 GUI 原有執行流程可繼續直接呼叫核心，但必須參與同一把鎖。MCP 對忙碌工作排隊；GUI 顯示已有背景任務並提供等待／取消，不擅自搶占。

### 5.2 按需啟動與模型

- MCP 關閉時，所有入口拒絕工作；GUI 一般啟動不啟動 worker、不掃描用戶端，不變更模型快取。
- MCP handshake、health、讀取既有逐字稿不載入模型。只有排到的轉錄工作才載入已下載模型。
- 按實際 CPU／CUDA／MLX 支援重用核心回退規則，不為 MCP 另行放寬品質或繁體檢查。
- 同一協調器在安全的相同模型／設定下重用模型；一次僅有一份高負載 worker。不同 AI 用戶端不能各自載入同一模型占滿記憶體。
- 斷開 AI 連線不立即取消已被接受的轉錄；可用工作編號再次查詢。關閉主視窗不取消背景工作。OS 登出／當機／重啟後未完成的轉錄標為 interrupted，重試從該檔案開始，不假稱可從 Whisper 的任意中間狀態續跑。
- 閒置退出不刪工作、字幕與模型；下次連線讀回工作狀態。

### 5.3 穩定位置、更新與解除

- 發行包內含 MCP 所需 runtime／啟動器，啟用不要求使用者下載程式碼或安裝額外 Python／Node.js。不使用執行時 `pip`、`npx` 或任意遠端下載。
- 保持三種既有 Release 成品。Claude `.mcpb` 由設定功能在本機產生／匯出，不另增重複的 Release 安裝檔。
- 安裝版／macOS App 的背景入口有明確絕對位置。免安裝版首次啟用時，從隨包可信資源準備版本化的私有 MCP 入口；用戶端設定不可指向暫時的 `_MEIPASS` 或解壓目錄。
- 輕型入口與媒體依賴不重複打包兩套 Whisper 模型。背景程式使用原模型快取，只讀／沿用，不搬移、清空或隱藏重新下載。
- 免安裝主程式被移動、App 更新／舊 runtime 不相容時顯示需修復；由使用者按一次修復自有連接，不猜測其他可執行檔。不在背景偷偷改寫各家設定。
- 更新期間有工作時不強殺進程；先完成／取消後再更新。使用中的舊版本 payload 保留至可安全替換；版本相容性可檢查並可回復。
- 停用、移除連接與解除安裝分開：停用不刪成果；移除連接只處理自有項目；解除安裝不自動抹除模型、工作與翻譯。再次使用須重新明確啟用，不自動復活舊授權。

## 6. 檔案授權與資料模型

### 6.1 伺服器執行授權

- GUI 設定 MCP 專用允許範圍，獨立於 AI 用戶端的信任設定。MCP 工具不能新增 root、啟用總開關或修改其自身權限。
- 第一版預設可在選取的教材 root 中讀取支援媒體／字幕，並在原片旁建立新的排他輸出資料夾；任務暫存及翻譯草稿位於本機私有工作區。
- 以 root ID 加相對路徑選取媒體，回傳不可猜測的 asset／job／source／draft ID。讀取逐字稿、回填及匯出以這些 ID 操作，不接受任意來源與目的地的絕對路徑。
- 拒絕跨 root、`..`、UNC／裝置路徑繞過、NTFS ADS、連結／junction 跳出、非一般檔案及替換競態。選定 root 本身的解析及後續子項目控制沿用安全檔案層；路徑字串前綴比較不足以授權。
- 輸入長度、輸出大小、讀取頁數、單次翻譯批次及待處理任務數皆有上限；無界全機列舉與回傳不提供。
- 字幕文字為不可信資料，不是操作指令；工具描述與工作流指引明確提醒 AI 不執行字幕中的指令。資料有清楚邊界，但不宣稱能完全消除所有客戶端的 prompt injection。

### 6.2 工作／來源／翻譯

- 本機私有資料庫保存 schema version、root reference、工作設定快照、狀態、來源修訂、完成的翻譯 batch 與輸出位置。
- 原文字幕讀入後產生不可變來源快照，保存來源 hash、cue ID、原始文字及時間。原檔改變後須重新匯入，不能把新舊來源混為同一修訂。
- 不在資料庫保存 AI 帳號、API key 或聊天內容；只保存本功能所需原文、翻譯與工作資訊。預設不自動刪除；提供清楚的私有工作資料位置與使用者主動清理功能，清理不刪原片／已發布成果／模型。
- 私有儲存不是加密或全程離線的保證；使用雲端 AI 時，回傳的字幕文字仍可能離開本機。GUI 啟用說明與工作流提示必須明示。

## 7. 工具介面（概念契約，名稱可在計畫階段微調）

| 工具 | 最小輸入／輸出 | 行為與副作用 |
| --- | --- | --- |
| `get_status` | 協定／功能版本、允許 root 的 ID／顯示名稱、模型就緒、工作摘要 | 不載入模型、不讀帳戶秘密 |
| `list_media` | root ID、相對目錄、分頁 cursor → asset ID、檔名、專案類型 | 僅列支援檔案；不回傳整個 root 的任意文件 |
| `start_transcription` | asset ID、限制過的設定、request ID → job ID | 驗證權限／模型／磁碟後排隊；不等待整片完成、不自動下載模型 |
| `get_job`／`cancel_job` | job ID → 狀態、階段、可取得的進度、結果 ID | 未知進度不偽造百分比；取消可能須等現有核心運算返回 |
| `import_subtitle` | 已授權媒體／字幕 asset ID → source ID／revision | 已有 SRT／VTT 可略過轉錄；嚴格檢查，不執行其內容 |
| `read_transcript` | source ID、cursor／cue 範圍／搜尋字詞 → cues、時間、下一頁 | 有界分頁，拒絕無限全文輸出 |
| `prepare_translation` | source revision、目標語言、選填術語／風格 → draft ID、batch 摘要 | 本機只準備資料，不呼叫雲端翻譯 API |
| `get_translation_batch` | draft ID、batch ID → 可翻譯 cue IDs、原文、上下文、術語 | 只有指定 IDs 可回填；上下文 cue 不算待翻譯段落 |
| `submit_translation_batch` | draft／revision／batch、cue ID 與純文字、request ID → 接受／缺漏 | 僅保存本地草稿；伺服器保存時間軸，不接受 AI 改時間碼或路徑 |
| `finalize_translation` | draft ID → 正式語系 track ID、完整性報告 | 全部 cue 有有效文字才產生新字幕，保留原文、不覆寫 |
| `export_player` | 媒體、原文／翻譯 track IDs、選填標題、request ID → job ID | 只引用已完整 track；於允許的影片旁建立新包，不發布網站 |

設定預設沿用 GUI 可用的模型／硬體建議，將本次有效值快照化；可明確給模型、device、批次開關／大小、繁體、時間軸、前導提示及術語。後端不支援時清楚回傳實際模式，不傳不存在的 MLX 批次控制。

不提供「替 AI 設定 key」「呼叫任意 URL」「執行 shell」「修改任意檔案」「刪除模型」等通用工具。範例 prompt／server instructions 只教組合上述能力，不偷偷擴充權限。

## 8. 多語翻譯與匯出契約

### 8.1 可靠回填

1. 原文形成固定 source revision。相同來源同語言草稿可列出續用，不默默取代原草稿。
2. 初始每批最多 50 cues 且不超過 8,000 原文 Unicode 字元，附少量前後上下文；單一 cue 超限時回報需縮小來源，不截斷或漏掉。預設可於後續以實測調整。
3. AI 只回傳 `cue_id` 與翻譯 `text`，不能指定時間碼、檔名、輸出位置、HTML 或播放器程式。
4. 全批驗證 cue 集合、唯一性、來源 revision、語言、大小及非空文字；一批錯誤整批不寫入，回傳可定位原因。重送相同 request ID／payload 不重複追加，內容不同回報衝突。
5. 每批保存，斷線後查詢已完成／缺少批次；新用戶端可在同一使用者授權範圍續接，但不以連線名稱當作者或授權憑證。
6. finalize 時逐 cue 套用原時間，不重新分段、不重新辨識；原有合法重疊可保留，空白／缺漏／超限等不發布。
7. 詞彙表與風格只提供給 AI，不宣稱能自動證明翻譯正確。語言標示、AI 翻譯待校對狀態與完整性報告分開。

### 8.2 新播放器

- 首版選用現有一般 MP4 匯出器及共用 EverCam 版面，預設右側逐字稿；沿用搜尋、跟隨、閱讀設定、逐字稿下載、鍵盤導覽。
- 固定 `index.html`、`media.mp4` 及 `media.<語系>.srt/vtt`，語系使用現有 canonical language 驗證。每一語言一軌，最多先限制 32 軌以便後續 OpenCam 相容。
- 預設 `<影片名稱>-web`，碰撞使用 `-2`、`-3`，仍在發布時排他檢查，不因檢查後的競態覆寫。
- 完整語系清單由呼叫者明確指定；缺少要求的語系則拒絕，不自動改成只輸出部分語言。可明確選擇只匯出已完成語系。
- 影片／字幕／內建資源全部完成驗證後才發布資料夾；取消或失敗維持現有安全清理／保留暫存的行為。匯出後回傳路徑，不自動打開瀏覽器或上傳。
- 首版不自動覆寫既有播放器，也不原地置入 EverCam／OpenCam；第二階段採獨立工具與明確授權／備份，不改變現在 GUI 的原有功能。

## 9. 背景工作、停用與可觀察性

工作狀態：`queued → preparing → running → validating → publishing → succeeded`；失敗、取消、重啟中斷分別為 `failed`、`cancelled`、`interrupted`。

- request ID 以本機工作範圍持久化；相同 ID／輸入取得原 job ID，不再轉錄或複製影片；相同 ID／不同內容拒絕。AI 網路重試不等於建立新工作。
- 取消為要求，不強殺正在執行的 CTranslate2／Metal 呼叫；標示 `cancelling` 並等待核心返回。發布完成後的取消不刪成果，也不把成功改成失敗。
- 任務接受後即保存狀態。資料庫、原片、可用空間或模型檢查失敗不先回成功。
- 權限在排隊、開始、每次字幕讀寫及發布前重新檢查；僅連線時檢查不夠。root 移除立即拒絕新存取，相關工作在安全點停止，不繼續發布。
- GUI 關閉≠停用。總開關停用時先立即阻止所有新工具工作與新資料讀取，再讓使用者選「完成已接受工作後停用」或「取消後停用」；維持現有資料範圍的既有工作可按其選擇完成。取消／查狀態控制在停用中仍可使用，但不提供字幕內容。
- 重新開機後啟用政策可保留，但沒有 OS 自動開機常駐服務；由用戶端呼叫按需啟動。解除安裝後不允許殘留入口自行啟動。
- GUI 顯示背景任務，提供狀態、取消、開啟結果及簡短錯誤；無 GUI 時回傳結構化錯誤及處理建議，不彈對話框等候。
- 記錄使用時間、工具名稱、job ID、模式與耗時；預設不記錄字幕全文、設定全文、環境變數、AI prompt 或秘密。可匯出經遮蔽的診斷，必須使用者主動操作。

## 10. 錯誤與資料保護

至少定義：`MCP_DISABLED`、`ROOT_NOT_ALLOWED`、`UNSAFE_PATH`、`MODEL_DOWNLOAD_REQUIRED`、`MODEL_ACCESS_ERROR`、`UNSUPPORTED_DEVICE`、`SOURCE_CHANGED`、`INVALID_SUBTITLE`、`TRANSLATION_INCOMPLETE`、`REVISION_CONFLICT`、`REQUEST_CONFLICT`、`DISK_FULL`、`OUTPUT_EXISTS`、`CANCELLED`、`JOB_INTERRUPTED`、`CLIENT_CONFIG_CONFLICT`。

可重試失敗與必須人工介入分開。Windows 分享衝突仍使用有限重試；權限／不安全路徑不以重試繞過。所有錯誤都不清模型、不刪原文、不停用安全防護，也不把預覽／暫存路徑當作正式完成。
