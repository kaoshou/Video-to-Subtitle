# Windows 安裝完成後啟動：處理方式與驗證

## 問題與修正範圍

使用者回報：一般雙擊安裝程式，完成後勾選啟動，讀取已下載模型時出現 `WinError 448`；關閉後從捷徑手動開啟同一程式，則可正常使用。

這個對照顯示啟動環境有差異，不能據此認定模型損毀，也尚未證實是安裝器的 RedirectionGuard 繼承所致。

- 模型讀取限制使用獨立的 `ModelCacheAccessError`，不再進入損毀快取清除詢問。
- 主畫面、模型管理與批次轉錄均保留快取；讀取受阻的按鈕顯示「檢查存取」。
- 安裝完成的啟動入口使用 `--from-installer`。這個短暫入口不建立主介面、不讀取模型，僅請既有桌面 Explorer 啟動同一個已安裝 EXE，且不轉送此旗標，避免遞迴。
- 此路由依 Microsoft 的 ExecInExplorer 範例取得桌面的 COM 介面，不以一般 `ShellExecuteEx` 呼叫冒充桌面代理。
- 桌面啟動失敗時，提示從捷徑手動開啟；不回退到安裝器直接建立子程式，不停用 RedirectionGuard，不重建或刪除模型連結。
- 既有安裝／解除安裝設定與 `safe_files.py` 安全防護保持不變。

## 本機自動測試

測試使用拋棄式合成快取與 COM／Windows API 邊界替身，不使用使用者模型。

```sh
VTS_RUN_GUI_TESTS=1 python -m unittest discover -s tests
```

重點包括：錯誤碼 5／32／448 不被判為損毀、載入階段拒絕讀取、下載後檢查拒絕讀取、三個介面入口不詢問清除、模型權重未改動、桌面 COM 呼叫參數、ABI 與失敗後資源釋放。

macOS 上的邊界測試不能證明 Windows 實際的安裝完成後啟動已正常；須完成下方檢查才可作此宣稱。

## Windows 實機驗證清單

使用拋棄式 Windows 測試帳號及專用模型目錄，不操作既有使用者安裝。原有 `scripts/smoke_windows_installer.py` 的靜默安裝／直接啟動測試仍有用途，但不等同下列互動流程。

1. 在一般使用者權限下準備可正常讀取的模型快取；包含合法的使用者建立的快取符號連結。記錄檔案大小、雜湊與數量。
2. 一般雙擊新建置的安裝包，保留 Windows 與安裝器安全防護，完成安裝時勾選「啟動 Video to Subtitle」。
3. 確認只出現一個正常主介面，沒有遞迴啟動或快取損毀提示；確認實際程式由桌面 Explorer 啟動，而非只確認安裝器入口曾執行。
4. 選用該模型執行短片轉錄，確認模型確實可載入，未重新下載、刪除或修改既有快取。
5. 關閉程式後，分別從開始選單與桌面捷徑開啟，再次完成相同操作，比對結果。
6. 比對前後快取雜湊、大小與數量，並保留安裝日誌、啟動來源與安全政策診斷資料。
7. 在無法取得桌面代理的測試環境，確認顯示手動啟動指引，且不直接啟動受限子程式、不清除快取。

發布流程的跨平台測試及靜默安裝測試，與上述互動式驗證分開記錄；不得以建置成功代替實際操作結果。
