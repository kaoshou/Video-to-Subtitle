# Video to Subtitle 完整使用手冊（繁體中文）

> 影音內容只在本機處理，不會上傳至雲端。首次下載語音模型，以及啟動時自動或手動檢查 GitHub 更新時需要網路；這些連線只取得模型或版本資訊。自動產生的字幕仍應由人工核對。

Video to Subtitle 是以 faster-whisper（Windows／一般 CPU 與 CUDA）及 mlx-whisper（macOS Apple Silicon）為核心的桌面工具，可將影音轉成 SRT、VTT、TXT、TSV 或 JSON，並在同一套程式內完成字幕校對與影音同步預覽。

## 下載與系統需求

請只從 [GitHub Releases](https://github.com/kaoshou/Video-to-Subtitle/releases/latest) 下載最新版。Windows 發行檔為 `VideoToSubtitle.exe`，macOS 發行檔為 `VideoToSubtitle.dmg`。

第一次使用某個 Whisper 模型時需要網路連線。模型下載完成後，一般轉錄、字幕校對及 EverCam 轉換均可在本機執行。模型需要約 75 MB 至 3.1 GB，請預留比模型標示大小更多的暫存與解壓縮空間。

### Windows 安裝與啟動

1. 下載最新的 `VideoToSubtitle.exe`。
2. 將檔案放在有寫入權限的位置，例如自己的文件資料夾。
3. 雙擊執行。若 Windows SmartScreen 顯示保護提示，先確認檔案確實來自本專案的官方 Releases，再依系統畫面選擇顯示詳細資訊並執行。
4. 使用 CPU 不需要額外設定；CUDA 為具備相容 NVIDIA 顯示卡之使用者的選用加速功能。

### macOS 安裝與啟動

1. 下載最新的 `VideoToSubtitle.dmg`。
2. 開啟 DMG，將 VideoToSubtitle 拖入「應用程式」。
3. 第一次啟動若被 macOS 阻擋，請先確認 DMG 來自官方 Releases，再於 Finder 對程式按住 Control 點按並選擇「打開」，或依「隱私權與安全性」畫面的提示允許開啟。
4. Apple Silicon Mac 可在「運算單元」選擇 `mlx`；若 MLX 無法載入，程式會提供訊息並可改用 CPU。

v2.7.7 發行包已整合 PyAV 音訊解碼與執行 MLX 所需的元件。**使用發行版不需安裝 Python、FFmpeg 或 mlx-whisper。**

## 第一次轉錄

1. 點選「加入檔案...」，或把影音檔案拖曳到主視窗。支援 MP4、MP3、MKV、WAV、MOV、AVI、M4A、FLAC、OGG、WEBM。
2. 在「準確度（Model）」選擇模型。尚未下載的模型會標示 `[未下載]`；開始轉錄時會自動下載，也可以先按「下載模型」。
3. 選擇運算單元與輸出格式。一般轉錄用途建議先使用 `large-v3-turbo` 與 SRT；若要翻譯成英文，請依下方說明改選其他模型。
4. 視內容決定是否勾選「強制繁體中文」，並填入前導提示或熱詞。
5. 點選「開始轉錄（Start）」。清單中的檔案會依序處理，底部顯示目前進度與日誌。
6. 完成後可開啟字幕、開啟所在資料夾或進入「字幕校對」。輸出檔預設與原始影音放在相同資料夾，檔名相同、附檔名改為所選格式。

如果選用尚未快取的模型，第一次執行時間會包含模型下載；這不代表轉錄停住。可從進度文字查看下載量、速度與預估剩餘時間。

## 模型選擇指南

| 模型 | 預估大小 | 適合情境 |
| --- | ---: | --- |
| `tiny` | 約 75 MB | 快速測試、硬體資源有限，準確度較低 |
| `base` | 約 145 MB | 短內容與初步草稿 |
| `small` | 約 480 MB | 一般語音與速度優先的工作 |
| `medium` | 約 1.5 GB | 速度與準確度的平衡 |
| `large-v3` | 約 3.1 GB | 準確度優先，需更多記憶體與時間 |
| `large-v3-turbo` | 約 1.6 GB | **一般轉錄建議**；兼顧辨識品質、速度與資源需求 |

實際速度與記憶體用量會受到影片長度、語言、CPU／GPU、散熱及其他執行中程式影響，表格不代表所有硬體都能得到相同效能。

## 完整轉錄設定

### 運算單元

- **Windows `cpu`**：相容性最高，不需要額外驅動設定。
- **Windows `cuda`**：選用的 NVIDIA GPU 加速。需要相容的驅動與 cuDNN；請參考 [NVIDIA cuDNN](https://developer.nvidia.com/cudnn) 與 [CTranslate2 安裝文件](https://opennmt.net/CTranslate2/installation.html)。若載入失敗，切換回 `cpu`。
- **macOS `cpu`**：使用處理器轉錄，適合作為相容模式。
- **macOS `mlx`**：使用 Apple Silicon 的 MLX 加速。官方 DMG 已包含所需執行元件。

### 輸出格式

- **SRT**：最通用的字幕格式，包含序號與時間軸。
- **VTT**：適合 HTML5 網頁播放器及部分教學平台。
- **TXT**：只保留文字，方便閱讀、摘要與後續潤飾。
- **TSV**：以欄位方式保存時間與文字，適合試算表或資料處理。
- **JSON**：保留結構化結果，適合程式整合。

### 強制繁體中文與翻譯英文

「強制繁體中文」會在中文辨識後使用 OpenCC 轉為台灣慣用繁體文字。它不會代替人工校對，也不會修正所有專有名詞。

「翻譯為英文」會要求 Whisper 執行英文翻譯；啟用時，「強制繁體中文」不適用。需要保留原語言字幕時，不要勾選英文翻譯。

`large-v3-turbo` 不適合「翻譯為英文」：該模型未針對翻譯任務訓練，可能仍輸出原語言。需要英文翻譯時請改選 `medium` 或 `large-v3` 等支援翻譯的多語模型。

### 前導提示與熱詞補強

- **前導提示（Prompt）**：輸入一段完整語句描述講題、情境或文風，例如「這是一堂介紹資料庫索引的資訊工程課程」。它用來建立整體上下文。
- **熱詞補強（Hotwords）**：輸入以逗號分隔的人名、術語、產品名稱或程式識別字。也可以按「載入」，從每行一詞或逗號分隔的文字檔匯入，內容會與現有熱詞合併。

若同時啟用「強制繁體中文」，程式會把繁中引導語與自訂前導提示合併。提示與熱詞只能提高模型注意這些內容的機會，仍可能出現同音字或錯誤拼寫。

在 v2.7.7 中，Windows `cpu`／`cuda` 與 macOS `cpu` 使用的 faster-whisper 會把前導提示與熱詞送入辨識引擎。macOS `mlx` 只會把前導提示送入 MLX 辨識引擎；熱詞不會引導 MLX 辨識，只會參與後續文字處理。MLX 也不會把 VAD 靜音過濾與單字時間戳選項送入辨識引擎。若工作需要這些控制，請在 macOS 改用 `cpu`。

### 進階設定

按「顯示進階設定」可調整 VAD 靜音過濾、單字時間戳、文字間距、英文大小寫修正、CPU 執行緒、標點處理及斷句策略。預設的自然語意與停頓斷句會參考語音停頓、標點與單字時間軸；防溢上限預設為 35 字，用來避免單條字幕過長，但不是強制每句都等長的硬切規則。

除非已理解用途，建議先保留預設值。語音過短、背景噪音很大或音樂占比高時，調整 VAD 仍不一定能消除所有幻覺文字。

## 多檔案批次處理

可以重複按「加入檔案...」或一次拖入多個檔案。程式會過濾不支援的格式、依清單順序處理，並在日誌顯示目前檔案及整批進度。

- 按「清除清單」可在開始前移除所有待處理項目。
- 執行中按「取消（Cancel）」並確認，可停止目前批次任務；已完成的輸出會保留。
- 批次完成視窗會逐項提供「開啟字幕」、「開啟目錄」與「字幕校對」。
- 少量或大量檔案會使用適合的完成清單版面；這不影響輸出內容。

## 字幕校對器

按主畫面的「編輯現有字幕檔」，或在任務完成視窗按「字幕校對」，即可開啟 SRT、VTT 或 TXT。SRT／VTT 以時間軸清單編輯；TXT 使用全文模式。

### 影音同步預覽與播放控制

選擇與字幕對應的影片後，點選任一字幕列會跳到該時間；播放時，字幕清單會跟隨目前畫面。右側播放器提供：

- 播放／暫停與前後 5 秒跳轉。
- `1.0x`、`1.25x`、`1.5x`、`2.0x`、`0.75x` 循環播放速度。
- 音量滑桿與一鍵靜音；解除靜音會回復先前音量。
- 「CC」開關，在影片畫面上疊加目前字幕，文字修改後同步更新。
- 分割面板可拖曳調整字幕與影片區域；按 F11 或視窗按鈕可切換最大化。

若未選影片，仍可編輯字幕文字與時間軸。

### 編輯時間與文字

先選取字幕列，再在下方修改開始時間、結束時間與文字。可用 `-0.5s`、`+0.5s` 快速微調時間，或用「上一條（Alt+↑）」與「下一條（Alt+↓）」連續校對。搜尋欄會協助定位含有指定文字的字幕。

編輯後按「儲存並關閉（Save & Close）」寫回原檔；關閉前請確認時間格式與文字內容。

自 v2.7.8 起，字幕儲存與 EverCam 部署會拒絕相關輸出路徑中的符號連結或 Windows junction／reparse point，避免覆寫非預期檔案。若收到拒絕訊息，請先確認來源可信，再把需要的內容複製成一般檔案／資料夾後重試。EverCam 首頁備份失敗時會停止部署；重新部署會保留原首頁備份與額外自訂資源。單一檔案會安全替換，但整批部署不保證全部成功或全部復原；磁碟空間不足時請保留備份並排除原因後重試。

### 分割、合併與鍵盤操作

- **Ctrl+K**：把文字游標放在目前字幕文字中間，依前後文字比例將該字幕與時間軸分成兩條。
- **Ctrl+J**：把目前字幕與下一條合併，文字及起訖時間會接合並重新編號。
- **Alt+↑／Alt+↓**：切換上一條／下一條字幕。
- **空白鍵**：播放或暫停影音預覽。
- **F11**：切換字幕編輯器最大化狀態。

分割前請把游標放在合適位置；最後一條字幕無法再與下一條合併。操作後仍需播放檢查時間點。

## 模型儲存管理

主畫面右下角的「模型儲存管理」提供以下功能：

- 顯示目前模型快取路徑與磁碟剩餘空間。
- 以 `[已下載]`／`[未下載]` 標示模型狀態，並列出預估大小。
- 點「立即下載」預先快取模型；下載支援取消與斷點續傳，再次下載可繼續未完成內容。
- 變更模型儲存路徑，例如把模型移到空間較大的磁碟。變更路徑不等同自動搬移舊快取；請在新路徑重新確認模型狀態。
- 清除指定模型快取以釋放空間；之後使用該模型時需要重新下載。

預設快取通常位於 Windows 的 `C:\Users\使用者名稱\.cache\huggingface\hub`，或 macOS 的 `/Users/使用者名稱/.cache/huggingface/hub`。若預設路徑無寫入權限，程式會提示改用其他可寫入位置。

## 離線使用

離線前先在「模型儲存管理」下載需要的模型，確認選單顯示 `[已下載]`，並用一小段影音完成測試。離線環境下可轉錄、校對字幕及進行 EverCam 網頁轉換，但無法下載新模型或檢查 GitHub 最新版本。

若離線時誤選未下載模型，程式會顯示網路／模型載入說明並恢復介面，不應直接關閉程式。改選已下載模型即可繼續。

## EverCam 數位課程

程式可辨識包含 EverCam `config.js` 與影音檔的課程資料夾：

若課程已經有字幕，不必重新轉錄。可直接在主畫面按「EverCam 網頁轉換」開啟獨立工具，再選擇單一課程資料夾、使用「批次掃描母目錄」尋找多個課程，或把課程資料夾拖入視窗。

播放器會讀取課程目錄中的 `media.srt`、`media.vtt`、`media.<語言>.srt` 或 `media.<語言>.vtt`。TXT、TSV 與 JSON 不能直接提供播放器需要的字幕時間軸；若要先由本程式轉錄再建立 EverCam 播放器，請選擇 SRT 或 VTT。

1. 把整個課程資料夾拖入主畫面，或選擇課程內的影音檔／`config.js`。程式會向上尋找課程根目錄並標示 EverCam 課程數量。
2. 依一般流程產生字幕。完成視窗會為 EverCam 項目顯示專屬徽章與「EverCam網頁轉換」。
3. 單一課程可立即轉換；多個課程可按「一鍵轉換全部的 EverCam 網頁」。
4. 轉換器會把字幕標準化到課程目錄、原生產生 `subtitles-data.js`，並部署可搜尋、可切換字幕且支援行動裝置的 HTML5 播放器。
5. 第一次替換既有首頁前，原始 `index.html` 會備份為 `index.evercam-original.html`。已是新播放器或已存在備份時，不會重複覆蓋原始備份。
6. 完成後程式會用預設瀏覽器開啟新播放器供立即檢查。

請保留整個課程資料夾結構，不要只移動新的 `index.html`。若檔案權限不足，請把課程複製到自己可寫入的位置後再轉換。

## 更新程式

「關於本程式」會顯示目前版本並提供「檢查更新」。程式只向 GitHub 查詢版本資訊；若有新版，可前往官方 Releases 下載。更新前先關閉正在執行的轉錄與模型下載工作。

Windows 直接以新版 EXE 取代舊檔；macOS 重新掛載新版 DMG，將 App 拖入「應用程式」並選擇取代。Whisper 模型通常存放在獨立快取目錄，更新程式本身不會主動清除它們。

## 常見問題

### 模型下載失敗或顯示離線

確認網路可連至 Hugging Face，稍後再試。已下載一部分的模型通常可續傳。若程式判定快取損毀，可依提示清除該模型快取後重新下載。

### 磁碟空間不足或沒有寫入權限

開啟「模型儲存管理」，選擇空間充足且自己可讀寫的資料夾。Windows 路徑過長時，可改用較短的位置，例如 `D:\models`。

### Windows CUDA 無法使用

確認 NVIDIA 驅動、CUDA／cuDNN 與 CTranslate2 支援版本相容。CUDA 不是必要條件；切回 `cpu` 可繼續轉錄。

### macOS MLX 載入失敗

先確認使用的是官方 v2.7.7 或更新 DMG，並把 App 完整複製到「應用程式」。重新開啟後仍失敗時，可先選 `cpu` 完成工作，再到 GitHub Issues 提供 macOS 版本、晶片型號與日誌中的完整錯誤。

### 字幕內容不準確或斷句不理想

改用較大的模型，提供講題前導提示與專有名詞熱詞，並確認音訊清楚。完成後使用字幕校對器修正文字與時間軸；任何模型都不能保證完全正確。

### 字幕編輯器沒有聲音或畫面

確認選到與字幕對應且格式受支援的影音檔，檢查播放器音量與靜音狀態。仍無法播放時，可先在編輯器完成文字校對，並在 Issues 附上格式與錯誤日誌。

### EverCam 轉換按鈕沒有出現

確認選取的資料夾或上層目錄包含 `config.js` 與課程影音檔。一般影音不是 EverCam 專案，不會顯示此按鈕。

## 從原始碼執行

> 本節只供開發者使用。一般使用者應下載 Releases 的 EXE 或 DMG。

建議使用 Python 3.11（專案支援 Python 3.10 至 3.12）。建立虛擬環境後安裝核心依賴：

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS / Linux: source .venv/bin/activate
pip install customtkinter tkinterdnd2 faster-whisper opencc av pillow sounddevice pyinstaller
```

macOS 開發者若要從原始碼使用 MLX，再安裝：

```bash
pip install mlx-whisper
```

啟動與打包：

```bash
python SubtitleTranscriber.py
pyinstaller VideoToSubtitle.spec
```

成品位於 `dist/VideoToSubtitle.exe` 或 `dist/VideoToSubtitle.app`；macOS 正式 DMG 仍以專案 CI 產物為準。
