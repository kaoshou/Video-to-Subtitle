# AI 工具連接（可選 MCP）

MCP 讓支援本機工具的 AI 客戶端在本機轉錄、讀取字幕、分批翻譯，再建立多語字幕播放器。功能預設關閉；一般轉錄不需要啟用。首次啟用採一般模式，可直接在 AI 對話指定完整影音／字幕路徑，不必先加入資料夾。啟用後背景服務可獨立工作，不必一直開著主視窗。

本工具不要求填入 API key。翻譯由你選用的 AI 客戶端與帳號處理，可能使用訂閱額度、消耗 token 或產生額外費用；免費額度、速率限制與資料政策由該服務決定。一般 ChatGPT／Gemini 網站不會因為寫入本機 MCP 設定就自動連上。

## 啟用與測試

1. 在主畫面下方、靠近「模型儲存管理」的位置，按「AI 工具連接」。視窗會讀取既有權限；單純開啟不會啟用或改寫 AI 客戶端設定。
2. 在「開始連接」步驟 1 開啟「啟用 AI 連接」，按「套用權限」。一般模式可處理目前使用者有權讀取的影音與字幕，並在影片旁建立新的播放器資料夾。需要縮小範圍時，至「進階管理」開啟「僅允許指定資料夾」、加入資料夾並套用。既有受限設定會保留；可在此關閉限制並套用，切換為一般模式。
3. 若需要語音轉錄，先在既有模型管理介面下載模型。MCP 發現模型缺少、不完整或無法讀取時會拒絕轉錄，不會代為下載、修復或刪除模型。已有 SRT／VTT 可直接匯入。
4. 在步驟 2 選擇 AI 工具，按「偵測工具」，再按「設定此工具…」。確認設定路徑、授權範圍、新舊項目與備份提示後，才同意寫入。Claude Desktop 會改為提供匯出 MCPB 安裝檔；Windsurf 與其他 MCP 工具提供手動設定。這不會跳過客戶端自身的信任與工具批准，也不會自動重啟 AI 客戶端。
5. 在步驟 3 按「測試本機連接」檢查本機 STDIO 協定與背景服務。接著在 AI 客戶端重新載入設定、審閱工具權限，提供完整影片路徑並要求處理，確認該客戶端連線。

「偵測到」、「設定完成」、「本機自我測試通過」和「真實 AI 客戶端連線成功」是不同階段。未知格式、明確不支援的版本、唯讀／管理員管理設定、JSONC 或衝突項目會轉為手動設定，請勿改寫其他工具的設定來繞過限制。

偵測結果分開呈現「程式」、「設定檔」與「連線」。未辨識到程式位置不等於沒有安裝；若已找到設定檔，仍可繼續設定。Windows 桌面程式位置與 Codex 的目前使用者套件登錄也會納入偵測；僅讀取安裝中繼資料，不啟動 AI 工具，也不將設定檔存在視為安裝或連線證明。

設定視窗的操作按鈕可用 Tab／Shift+Tab 巡覽、Enter／Space 啟用。手動設定與測試資訊會開在獨立視窗，可使用「複製內容」，不再與主頁產生雙層捲軸。「工作狀態」分頁提供更新、取消與開啟播放器；「進階管理」集中其他設定檔、啟動檔修復、停用存取與私人工作資料清理。清理仍需預覽與確認。

## 資料如何流動

設定視窗的「選取其他設定檔」可指定另一個已知格式的位置。若環境覆寫是相對路徑或偵測結果不明確，必須先明確選取用戶端使用的檔案，再經格式預覽與確認；不會直接套用猜測的預設位置。

```text
已授權的本機影音 → 本機模型轉錄 → 字幕文字分批交給 AI
                                     ↓
影片旁的新多語播放器 ← 伺服器保留原時間軸 ← AI 回傳純文字譯文
```

本機模型處理影音；外部 AI 客戶端可能把讀取的字幕、詞彙表與翻譯要求送往雲端。這不是全程離線承諾，請先確認教材、學生資料與機密內容是否適合交給選用的服務。私人狀態目錄有檔案權限保護，但不是加密資料庫。

一般模式允許透過 `list_media` 提供絕對檔案或資料夾路徑，僅列出支援的影音／字幕；後續處理仍使用伺服器識別碼。限制模式只接受指定資料夾內的路徑或根目錄 ID。兩種模式都驗證目錄與檔案身分、拒絕符號連結，不提供 shell、網址下載、帳號設定或模型管理工具。字幕和詞彙表是待處理資料；即使其中出現「忽略前述規則」等文字，也不能當作操作指令。

設定修改前會備份整份舊設定，可能包含其他伺服器的秘密，請妥善保管私人備份。移除時只移除本工具管理且未被外部修改的項目，保留後來新增的其他設定；不會整份回復舊檔覆蓋新內容。

## 翻譯與播放器流程

### 開始前確認設定

AI 可先呼叫 `preview_transcription`，以影片的 `asset_id` 及選用的 `settings` 查看實際解析的模型、運算單元、批次策略、模型快取狀態與播放器預計輸出位置。預檢不啟動工作、不載入或下載模型；`hardware_verified: false` 表示快取完整不等於硬體已通過實際推論。字幕先保存在私人工作區，網頁播放器才另建於來源旁。

已明確指定設定就可直接執行，不必每次重問；缺少重要選擇、模型不可用，或 AI 想改用另一模型／策略時，才應詢問使用者。開始工作仍會重新驗證，不因預檢曾通過就略過安全與模型檢查。工作查詢 `get_job` 亦附 `execution_plan`，不自動改成 tiny 或其他小模型。

可對 AI 提出：「請先列出我授權的課程，匯入指定影片的中文字幕，翻成英文和日文，保留原時間軸，最後輸出這兩種語言的播放器；完成後提醒我人工校對。」先確認 AI 選對檔案與語言，再允許後續工具呼叫。

工具會回傳各自的輸入結構，AI 應依實際 schema 操作：

1. `get_status` 查看 `access_mode`。一般模式用 `list_media({"path":"C:\\課程\\media.mp4"})` 取得指定檔案，或指定課程資料夾分頁列出影音與字幕；限制模式亦可使用已設定的 `root_id`。`path` 和 `root_id` 擇一提供。
2. `start_transcription` 接受轉錄工作後，用 `get_job` 查詢；或用 `import_subtitle` 匯入現有字幕。
3. `read_transcript` 分頁閱讀／搜尋；每種語言先用 `list_translation_drafts`（source ID、language，最多每頁 25 份）找回既有草稿、已完成／缺少批次及正式 track ID。新客戶端不需要記得舊 request ID；需要另一份草稿才用 `prepare_translation` 建立指定來源版本的草稿，不會覆蓋既有翻譯。
4. 用 `get_translation_batch` 讀取批次，再用 `submit_translation_batch` 回傳相同 cue ID 的純文字。每批最多 50 段、8000 個來源 Unicode 字元；另附前後各最多兩段、各 2000 字的唯讀上下文，不可回填上下文 cue ID，也不能由 AI 修改時間軸。
5. 所有批次完成後，對每種語言執行 `finalize_translation`。以明確的已完成 `track_ids` 呼叫 `export_player`，再查詢匯出工作。最多選 32 種語言；要求的語言未完成時不會偷偷省略。若只想先匯出部分語言，請明確指定。

譯文標記為待人工審閱。來源字幕改變會使舊版本失效，需重新匯入／轉錄；不要拿舊 cue ID 拼接新來源。重送完全相同的 `request_id` 與內容會取得原結果，內容不同會衝突。已失敗或中斷的請求可能需要明確使用新的 request ID 重試；不會假裝從模型解碼途中接續。

### 換對話或中斷後接續

可對 AI 說：「請查詢這部影片以前的字幕與翻譯工作，保留已完成部分，只接續尚未完成的日文翻譯。」重新用 `list_media` 選取影片後，`list_work(asset_id)` 能找到原字幕來源、工作狀態、翻譯草稿、完成／缺少批次數與建議下一步，不必記住舊工作代碼。每頁預設 20 筆、最多 50 筆；依 `next_cursor` 繼續讀取。

`revision_valid: true` 的草稿才可接續；再用 `list_translation_drafts` 查缺少的 batch ID，保留已完成批次。來源已變更會標示需要重新匯入，權限撤回的內容不會提供。**已完成的轉錄不用重做；語音辨識執行途中若程式中止，則需明確重新開始並使用新的 request ID，不支援從任意秒數恢復模型解碼。**

工作查詢會回報階段、實際可得的進度及開始／結束時間、處理耗時；排隊不算入處理耗時。百分比是該階段的比例，不是整項工作的預測完成比例。MLX 原生辨識等沒有逐段進度的階段顯示處理中，不估算虛構百分比或剩餘時間。

### 翻譯品質與專有名詞

既有的 `glossary` 自由文字仍可使用。需要可自動比對的術語規則時，可在 `prepare_translation` 加入 `glossary_terms`（最多 50 組，每個詞最多 100 字元）：

```json
{"glossary_terms": [{"source": "machine learning", "target": "機器學習"}]}
```

此規則只適用該份草稿的目標語言。程式把詞彙表交給 AI，並檢查來源有該詞時，譯文是否包含指定對應詞；英文詞比對會考慮單詞邊界，避免把 `Unity` 誤配為 `community`。含義相同的其他譯法仍可能被提醒，這是詞彙一致性檢查，不是語意判分。衝突或空白的術語規則會拒絕；術語內容也是待處理資料，不是執行命令。

| 提醒代碼 | 運作方式 | 使用方式 |
| --- | --- | --- |
| `long_text` | 單段譯文超過 120 個非空白 Unicode 字元。 | 檢查是否需精簡，程式不自動刪字。 |
| `reading_speed` | 非空白字元數除以原段落秒數超過 25。 | 檢查是否讀得完；不延長或修改時間軸。 |
| `possibly_untranslated` | 已知來源與目標為不同主語言，至少 20 字元、具有句子特徵，且正規化後全文相同。 | 只是疑似未翻譯；短名稱、同主語言與未知來源語言不使用此規則。 |
| `glossary_mismatch` | 來源包含明確指定術語，但譯文沒有指定對應詞。 | 校對翻譯或調整下一份草稿的術語規則。 |

`finalize_translation` 回傳並保存 `review`：全部待校對段數、各原因數量與前 200 筆參考。透過 `read_review(track_id, cursor, limit)` 可讀完所有提醒（每頁最多 50 筆），不因詳細資料分頁而少算總數。一段可有多個原因，因此各原因加總不等於段數。每筆附原段落時間與 cue ID，不改字幕內容。

漏 cue、空白譯文、額外 cue 或嘗試回填時間軸仍屬錯誤，不能以「只是提醒」通過。**零提醒不代表翻譯正確**；所有 AI 翻譯仍標示需人工審閱。既有匯入字幕若沒有檢查紀錄，回報 `not_checked`，不補稱為零問題。

轉錄成功後，`get_job.result.transcription` 回報該次實際使用的 `model`、`device` 與 `backend`，例如 `{"model":"medium","device":"cuda","backend":"faster-whisper"}`。這份資料會保存於工作與字幕來源，不受後來主畫面更改模型影響。「AI 工具連接 → 工作狀態」也會顯示「轉錄模型：medium · CUDA · faster-whisper」；MCP 指引要求 AI 在完成回覆告知使用者。

後續翻譯、輸出網頁仍保留來源的轉錄資訊，播放器匯出結果以 `transcriptions` 清單回報，可區分語音辨識模型與 AI 翻譯服務。匯入既有 SRT／VTT 時不會假稱曾使用某個語音模型；舊紀錄沒有這份資訊時也不補猜。

### 完成後的摘要

「工作狀態」卡片與 AI 完成回覆可整理以下內容：

| 項目 | 資料與解讀 |
| --- | --- |
| 實際模型 | `transcription`／`transcriptions` 的模型、設備與引擎；不是後來主畫面的選擇，也不是外部 AI 翻譯模型。 |
| 處理耗時 | `elapsed_seconds` 為這項工作開始處理至完成的秒數，包含準備、重試及輸出，但不包含排隊。字幕工作和網頁匯出是不同工作，各有自己的耗時。 |
| 語言與段數 | 字幕結果的 `language`／`cue_count`；播放器結果的 `languages`／`cue_counts`。 |
| 待校對提醒 | 字幕結果的 `review`；播放器結果的 `review_by_language`。保留每語言的提醒段數、原因及是否檢查過，不因合併摘要漏掉某語言。 |
| 尚未檢查 | `unchecked_languages` 列出沒有檢查紀錄的語言；`review_count: null` 不等於零。 |
| 儲存位置 | 播放器的 `folder` 與 `index_path`；可按「開啟播放器」。字幕原稿先在私人工作區，AI 透過來源／字幕軌 ID 接續翻譯與匯出。 |

本機轉錄完成時也會把既有的低信心、疑似重複、時間軸重疊等校對規則彙整為段數與原因；信心提醒沿用辨識引擎證據與原本字幕比對，不是翻譯評分。MCP 目前只回報這類轉錄提醒的摘要，`details_available: false`；翻譯提醒則可透過 `read_review` 分頁查看段落位置。原有字幕編輯器的校對功能保留。

OpenCam／EverCam 原本保留的字幕也包含在播放器的語言與段數摘要內；沒有本工具檢查紀錄的保留字幕列為未檢查，不會套用其他語言的品質結果。

例如 AI 可回覆：「已使用 large-v3-turbo／CUDA 完成繁體中文字幕，共 136 段，處理耗時 1 分 12 秒；英文譯文有 3 段閱讀速度提醒，仍需人工校對。多語播放器已建立於影片旁的新資料夾。」數字必須取自該次結果，不能套用範例或依目前設定猜測。未有模型／耗時／檢查資料的舊紀錄不補造資料。

### 在對話中選擇已下載模型

可以對 AI 說：「請查詢 MCP 已下載的模型，列出狀態與目前預設值，等我選擇後再開始轉換。」AI 應先呼叫 `get_status`，依 `default_transcription` 告知預設模型／運算單元，並依 `model_catalog` 列出六種模型在 `faster-whisper` 與 `mlx-whisper` 的快取狀態。使用者選定後，以 `start_transcription.settings.model` 指定該模型，不自行改成較小模型。

首次使用、未儲存模型設定時，主程式與 MCP 都預設 `large-v3-turbo`；既有模型設定會保留。尚未下載預設模型時會提示先下載，不自動改用 tiny／small。從主畫面啟用 MCP 時會保存當時的模型選擇，也可在對話明確指定模型。

| `status` | 顯示與判斷 |
| --- | --- |
| `ready` | 已下載且通過既有模型載入器的檔案完整性檢查，`downloaded: true`。 |
| `missing` | 目前 MCP 設定的模型快取中未找到，`downloaded: false`。 |
| `incomplete` | 檔案／版本索引不完整或無法通過檢查，`downloaded: false`，不可當作已就緒。 |
| `unavailable` | 權限或磁碟等因素導致無法檢查，`downloaded: null`；不表示模型損毀或未下載。 |
| `unknown` | 使用單一模型資料夾時，其他模型規格無法可靠判斷，`downloaded: null`，不會把同一份權重列成六種已下載模型。 |

CPU 與 CUDA 共用 faster-whisper 格式；MLX 是另一種模型格式，不能因其中一種已下載就假設另一種也可用。清單依 MCP 儲存的模型位置檢查，不搜尋整台電腦，不回傳私人快取路徑，不載入模型、不啟動下載，也不清理檔案。`ready` 代表檔案快取就緒，硬體與實際推論仍由開始轉錄時的檢查決定。停用 MCP 時不檢查或提供模型清單。

匯出在原影片旁建立新資料夾；名稱碰撞會加 `-2`、`-3`，不覆寫原影音、字幕或既有播放器。請保留整包影片與網頁檔案。新播放器沿用逐字稿搜尋、點擊跳轉、跟隨播放、語言切換、閱讀設定、HTML／TXT 下載與鍵盤操作；播放器取得焦點時 Space 播放／暫停、方向鍵快退／快轉，輸入欄位保留原本按鍵用途。完整操作見[使用手冊](USER_GUIDE.zh-TW.md#網頁播放器的逐字稿搜尋)。

### 自動辨識 OpenCam／EverCam 與對應播放器

`list_media` 可指定專案資料夾或 MP4 的完整路徑；回傳的每個影音項目都有 `project_type`。資料夾即使名稱以 `.mp4` 結尾，仍會列出資料夾內的影音，不會當成影片檔。此工具列舉指定目錄的一層內容；批次課程請分別指定各課程目錄。

| `project_type` | 辨識與輸出方式 |
| --- | --- |
| `opencam` | 關聯的 `media.mp4`、`index.html` 與合法的 schema-v1 `opencam-player.js`。複製 OpenCam 播放器，保留章節、其他語系字幕及原資料備份，再合併選定字幕。沒有字幕的專案也可建立第一軌。 |
| `evercam` | MP4 同目錄有 `config.js`。保留原章節設定，套用內建 EverCam 現代化播放器，合併原有 `media.srt`／`media.<語系>.srt`／VTT 與選定字幕；新字幕優先取代同語系舊檔。 |
| `mp4` | 一般 MP4，輸出逐字稿播放器，不產生虛構章節。OpenCam 旁的其他 MP4 不會誤認為其關聯影片。 |
| `media` | 其他支援的影音，可轉錄；網頁播放器匯出仍需 MP4。 |

OpenCam 的 `project` 資訊另含標題、章節數與既有字幕語言。匯出預設 `player_type: "auto"`，依辨識類型選擇播放器；若使用者明確只需要一般 MP4 播放器，可指定 `"mp4"`。指定 `"opencam"` 或 `"evercam"` 而來源不符時會回報 `PROJECT_TYPE_MISMATCH`。

```json
{
  "asset_id": "list_media 回傳的影片 asset_id",
  "track_ids": ["已匯入或完成翻譯的 track_id"],
  "player_type": "auto",
  "default_subtitle": "zh-TW",
  "request_id": "export-course-001"
}
```

對 AI 可直接說：「請辨識這個 OpenCam／EverCam 課程，產生繁體中文字幕、翻譯成英文與日文，並保留章節輸出對應的多語播放器。」先完成所有指定語系，再呼叫 `export_player`；`get_job` 的結果會回報實際 `player_type`、輸出資料夾與 `index.html`。

三種類型都另建資料夾，原課程不會被修改。OpenCam 保留原匯出版本的播放器介面；EverCam 與一般 MP4 沿用本工具的播放器。專案設定只作為資料解析／複製，伺服器不執行匯入的 JavaScript；OpenCam 資料無效、檔案為連結或匯出期間專案已變更時會停止，請修正來源並重新列舉。每個專案資源檔限制 32 MiB，合計限制 64 MiB；目前 OpenCam 支援標準自含式的 index/data/media 結構。

## 背景工作、停用與運算單元

關閉主視窗、設定視窗或 AI 客戶端，不會取消已接受的工作。按「停用存取」會立即拒絕新的內容存取；可選「完成已接受工作」或「取消已接受工作」。取消是合作式處理，正在執行的原生推論可能需先返回，不會強制終止模型程序。

只移除已授權資料夾可在模型忙碌時立即套用，不必重新開啟其他可能已卸載的磁碟。新增授權、更新授權身分及模型模式變更仍需等待模型所有權檢查。目錄被替換成另一個實體目錄時，舊授權不會自動繼承；請明確重新套用授權。缺少身分資料的舊授權需重新授權，不能直接恢復信任。列舉與入列保存檔案的裝置／inode／大小／修改及變更時間，等待期間檔案變動會停止舊工作；重新列舉後再提交。

「工作狀態」以來源檔名顯示「產生字幕／建立網頁播放器」、中文處理階段及實際模型，不虛構百分比。工作代碼、輸出位置及技術錯誤收在「詳細資訊」，內容未變時刷新不會收起說明。完成的播放器可按「開啟播放器」；開啟前重新驗證目前授權及發布時的目錄／索引檔身分，Windows 以實際 HTML 檔名交給系統預設程式。停用或成果已變更時不開啟；停用後仍可查工作中繼資料及請求取消，不回傳字幕或結果路徑。

啟用期間，背景服務在沒有工作與處理中的連線、閒置五分鐘後退出；停用後會在已接受工作完成且連線處理結束時正常退出。模型子程序先結束才釋放共用運算鎖，避免 GUI 與 MCP 同時佔用模型。工作之間可能重新載入已下載模型，不代表再次下載。

模型子程序另持有直到 OS 程序結束才釋放的模型駐留鎖。即使父 GUI／broker 意外退出，尚未結束的原生模型仍阻擋新模型、啟用與維護。直接 GUI 模型也保留駐留鎖至程序結束；不強制清除原生快取或終止模型。

## 私人工作資料位置與清理

設定視窗直接顯示實際位置。預設 macOS 為 `~/Library/Application Support/VideoToSubtitle/mcp`，Windows 為 `%LOCALAPPDATA%/VideoToSubtitle/mcp`；使用自訂測試位置時以視窗為準。暫存影音、逐字稿、翻譯與歷史預設保留，不會自動刪除。

「清理私人工作資料」先顯示確切位置、位元組數與範圍，再要求確認。此最小方案一次清除整組相依資料：私人影音副本、原文逐字稿、未完成及完成翻譯、工作歷史、AI 重試 ID；不提供只保留部分草稿的清理。請先完成或匯出要保留的資料。刪除無法復原，舊工作／來源／請求 ID 之後無法續用。

清理需先停用 MCP，並等待 broker、工作及模型所有權正常釋放；有活動擁有者時拒絕。已當機而無擁有者的未完成紀錄視為中斷資料，一併納入明確同意的清理。只刪除固定私人工作命名空間，不跟隨連結；原影音、已發布播放器、模型、授權政策、連接設定和完整客戶端備份保留。清理可回復已滿的工作／請求紀錄配額。

若清理中斷，新的內容操作與啟用會被阻擋；再次使用同一清理按鈕，審閱剩餘大小後確認續清。清理不經 AI 工具提供，也不會自動清除備份中的秘密。

CPU、NVIDIA CUDA 與 Apple Silicon MLX 沿用既有核心與硬體限制。GUI／MCP 的 CPU／CUDA 預設啟用批次與自動大小；既有 GUI 數字設定保留。MLX 使用原生路徑，不套用這些批次大小。效能依設備與模型而異，沒有保證加速倍數。

`start_transcription.settings` 保留整數 `batch_size`（2～32），另提供 `batch_mode`：

| 設定 | 行為 |
| --- | --- |
| 未提供 mode 與 size | `batch_mode: "auto"`；模型載入後、實際執行時估算，不在排隊時探測。 |
| 只提供 `batch_size: 8` 等既有整數 | 視為 manual，沿用既有呼叫方式且不讀資源。 |
| `batch_mode: "manual"` | 未給 size 時使用 4；可手動選 2～32，32 屬進階選項。 |
| `batch_mode: "auto"` 加 `batch_size` | 回報 `INVALID_ARGUMENT`；移除 size 或改為 manual。 |
| `batch_acceleration: false` | 使用標準路徑，略過自動資源探測。MLX/MPS 亦略過。 |

自動與 GUI 共用核心：依可用而非總 RAM／VRAM、模型、精度與實體核心保守估算，CPU 最高 8、CUDA 最高 16；資料不明保守選 2，嚴重 RAM 壓力可改用標準。完整預留空間與估算表見[使用指南](USER_GUIDE.zh-TW.md#批次加速試用)。這些數值未經跨硬體基準量測，不保證最快或避免所有 OOM；手動不改精度。OOM 與品質回退沿用安全重試，`get_job.result.batch_decision`（有提供時）回傳 `requested_mode`、`effective_size`（null 表示標準／原生）與有限 `reason` 代碼；自動規劃另附已知安全字串 `rationale` 說明可用資料／壓力／估算原因。回退時更新實際大小與 reason，rationale 保留原自動規劃依據；排隊紀錄保留的是要求的選擇。

若主視窗在首次啟用 MCP 前已載入直接運算的模型，請正常關閉並重新開啟，再啟用；這是釋放程序內原生快取的要求，不會刪除模型。其他工作持有運算鎖時，請等待完成或正常關閉持有模型的 GUI。

## 更新、移除與修復

封裝版使用獨立、固定版本雜湊的 STDIO 啟動器；明確啟用時才複製到私人穩定路徑。客戶端設定不會指向暫時解壓目錄。主應用程式仍是後端；移動免安裝版、刪除或搬移應用程式後，請開啟新的位置，使用「修復啟動檔」，重新套用啟用權限，再檢查客戶端設定與自我測試。缺少內附啟動器時需安裝包含 MCP 的封裝版，不能以系統 Python 冒充獨立 MCPB。

Windows MCP 版安裝程式在更新／解除安裝前以「完成已接受工作」停用存取；仍有背景工作或 GUI 持有模型時會中止維護，請等待或正常關閉 GUI 再試，不會強殺工作。即使維護中止，MCP 仍保持停用；完成後可自行重新啟用。不會刪除模型、結果、使用者設定或私人設定備份。

沒有 MCP 內附檔案的舊版不會被傳入其不支援的維護參數。若啟動器與驗證描述檔只剩其一，安裝程式會拒絕更新／移除，請先還原同版本完整安裝再停用；此時無法保證已成功撤銷授權。兩個辨識檔都被外部刪除時無法與舊版可靠區分，請在可用的主程式中先停用，勿以刪檔代替停用。

macOS 與免安裝版手動替換／刪除前，請先在「AI 工具連接」停用，等待工作完成並正常關閉 GUI。若還要移除 AI 客戶端項目，可先用「移除設定」；已由外部修改的項目請在該客戶端手動移除。保留的啟動器不代表仍有存取權，停用政策會持續阻擋新內容。

## 開發與驗證界線

來源碼啟用 MCP 需另裝可選套件：`python -m pip install "mcp>=1.30,<2" "tomlkit>=0.13,<1"`。一般 GUI 啟動不會匯入 MCP SDK。建置先執行 `pyinstaller MCPLauncher.spec`，再執行 `pyinstaller VideoToSubtitle.spec`；GUI 封裝內含經雜湊驗證的薄型啟動器，不另複製 Whisper／影音／GUI 相依套件。

來源煙霧測試：`python scripts/smoke_mcp.py`。完整封裝可執行主應用程式的 `--test-mcp`，或以腳本的 `--launcher`、`--backend` 指定兩個凍結執行檔；使用合成 MP4／字幕、暫存政策、空的子程序 PATH，完成匯入→兩語翻譯→播放器，不下載模型或修改真實 AI 設定。`--mcp-disable` 與 `--mcp-maintenance` 是可信本機管理入口，不是 AI 工具。

本次已驗證來源協定與 macOS arm64 的獨立啟動器／凍結後端合成流程。該本機建置未包含可用的 MLX 相依套件，是 CPU／MCP 煙霧建置，不代表完整正式版本認證。原生 Windows 安裝、ACL／命名管線、客戶端建立程序時的視窗行為、真實 AI 客戶端與 Claude MCPB 安裝同意、真實 CPU／CUDA／MLX 模型推論均需在相應環境另行驗證。

Windows 啟動器使用保留 STDIO 的 console 執行檔與 `hide-early`，而不是沒有標準輸入輸出的 GUI 執行檔；依 [PyInstaller 說明](https://pyinstaller.org/en/stable/feature-notes.html)，此模式只隱藏自己擁有的主控台。尚未做原生客戶端測試，不能保證所有情況都完全沒有視窗閃爍。
